# Kapitel 23: Lernstrategie, Lernportale & KI-Prompts

> [!IMPORTANT]
> Rust lernt man nicht durch passives Lesen allein. Dieses Kapitel zeigt, wie Sie Wissen aktiv abrufen, gezielt üben und KI als Tutor statt als Abkürzung verwenden.

## 23.1 Lernziele & Lernplan

Nach diesem Kapitel können Sie:

- einen realistischen Lernplan für Rust mit Wiederholung und Praxis erstellen;
- Lernportale wie Rustlings, Exercism und das Kurs-mdBook sinnvoll kombinieren;
- KI-Prompts so formulieren, dass sie Erklärungen, Feedback und Übungen liefern;
- die "Tutorial-Hölle" erkennen und durch kleine eigene Projekte verlassen;
- Compilerfehler als Lernmaterial dokumentieren.

Lernplan:

| Schritt | Thema | Ergebnis |
|---|---|---|
| 1 | Definition | Sie kennen Active Recall, Spaced Repetition und deliberate practice. |
| 2 | Motivation | Sie verstehen, warum Rust ohne Strategie frustriert. |
| 3 | Fehler | Sie sehen einen passiven Lernversuch scheitern. |
| 4 | Lösung | Sie bauen eine wiederholbare Lernroutine. |
| 5 | Tutorial | Sie planen eine 7-Tage-Übungswoche. |
| 6 | Deep Dive | Sie vergleichen Lernportale und KI-Rollen. |
| 7 | Übungen | Sie erstellen eigene Prompts und Aufgaben. |

## 23.2 Die Definition

Eine **Lernstrategie** ist ein bewusst gewähltes System aus Lernziel, Übung, Feedback, Wiederholung und Reflexion. Für Rust ist sie besonders wichtig, weil Syntax, Typsystem, Ownership und Borrowing gleichzeitig aufgebaut werden müssen.

Wichtige Begriffe:

| Begriff | Bedeutung |
|---|---|
| Active Recall | Wissen ohne Vorlage aus dem Gedächtnis abrufen. |
| Spaced Repetition | Inhalte zeitlich verteilt wiederholen. |
| Deliberate Practice | Gezieltes Üben knapp oberhalb des aktuellen Könnens. |
| Tutorial-Hölle | Viele Tutorials konsumieren, aber keine eigenen Probleme lösen können. |
| KI-Tutor | KI erklärt, fragt nach, bewertet und gibt Hinweise, statt nur fertigen Code zu liefern. |

## 23.3 Das Problem & die Motivation

Rust erzeugt am Anfang oft zwei falsche Eindrücke:

- Beim Lesen scheint alles logisch.
- Beim eigenen Schreiben bricht der Code sofort an Ownership- oder Typfehlern.

Das liegt nicht an mangelnder Begabung. Es liegt daran, dass passives Verstehen und aktives Anwenden verschiedene Fähigkeiten sind. Rust verlangt aktive Anwendung, weil der Compiler Ihr mentales Modell präzise überprüft.

> [!NOTE]
> Eine rote Compilerdiagnose ist kein Scheitern. Sie ist ein sehr genauer Hinweis darauf, welche Regel Ihr aktuelles mentales Modell noch nicht enthält.

## 23.4 Der naive Versuch

Ein typischer Lernversuch sieht so aus:

```text
1. Video ansehen.
2. Code aus dem Video kopieren.
3. Ausgabe prüfen.
4. Zum nächsten Video wechseln.
5. Nach zwei Tagen ein eigenes Programm beginnen.
6. Bei erstem Borrowing-Fehler abbrechen.
```

Als Rust-Code zeigt sich das oft so:

```rust
fn main() {
    let text = String::from("Rust lernen");
    println!("{}", erstes_wort(text));
    println!("{text}");
}

fn erstes_wort(text: String) -> String {
    text.split_whitespace().next().unwrap().to_string()
}
```

Zeile-für-Zeile:

| Zeile | Problem |
|---|---|
| `erstes_wort(text)` | Der `String` wird verschoben. |
| `println!("{text}")` | Der verschobene Wert wird erneut verwendet. |
| `fn erstes_wort(text: String)` | Die Funktion verlangt Besitz, obwohl sie nur lesen muss. |
| `unwrap()` | Leere Eingabe führt zu einer Panic. |

## 23.5 Die Anatomie des Fehlers

Der Compiler meldet:

```text
error[E0382]: borrow of moved value: `text`
```

Der Lernfehler dahinter:

- Der Code wurde kopiert, aber die Signatur wurde nicht bewusst gewählt.
- Es wurde nicht gefragt: "Muss diese Funktion Besitz übernehmen?"
- Der Compilerfehler wird als Hindernis betrachtet, nicht als Diagnose.

Speicheranalyse:

```text
text besitzt Heap-Daten "Rust lernen".
erstes_wort(text) verschiebt den Besitzer in die Funktion.
Am Funktionsende wird der Parameter gedroppt.
main hat keinen gueltigen Besitzer mehr.
```

## 23.6 Die Lösung

Lernstrategie und Code werden korrigiert:

```rust
fn erstes_wort(text: &str) -> Option<&str> {
    text.split_whitespace().next()
}

fn main() {
    let text = String::from("Rust lernen");

    match erstes_wort(&text) {
        Some(wort) => println!("Erstes Wort: {wort}"),
        None => println!("Kein Wort gefunden"),
    }

    println!("Original: {text}");
}
```

Warum dies besser ist:

- `&str` liest, ohne Besitz zu übernehmen.
- `Option<&str>` modelliert leere Eingaben.
- Der Owner `text` bleibt in `main`.
- Der Fehler wird in eine Regel übersetzt: "Lesefunktionen nehmen Referenzen."

EVA:

| Phase | Beschreibung |
|---|---|
| Eingabe | `&str`, ein geliehener Text. |
| Verarbeitung | Der Text wird in Wörter aufgeteilt. |
| Ausgabe | `Option<&str>`, eine geliehene Sicht auf das erste Wort. |

## 23.7 Kleines Tutorial: Eine 7-Tage-Rust-Lernroutine

### Schritt 1: Tagesziel formulieren

```text
Heute kann ich eine Funktion schreiben, die Text liest, ohne Ownership zu verschieben.
```

### Schritt 2: Mini-Aufgabe wählen

Beispiel:

```rust
fn anzahl_woerter(text: &str) -> usize {
    text.split_whitespace().count()
}

fn main() {
    let satz = String::from("Rust braucht aktive Uebung");
    println!("{}", anzahl_woerter(&satz));
    println!("{satz}");
}
```

### Schritt 3: Fehler absichtlich provozieren

Ändern Sie `&str` zu `String`. Notieren Sie:

- Welche Fehlermeldung erscheint?
- Welche Variable wurde verschoben?
- Welche Signatur wäre passender?

### Schritt 4: Wiederholen

Plan:

| Tag | Fokus | Aufgabe |
|---|---|---|
| 1 | Ownership | Move-Fehler erzeugen und erklären. |
| 2 | Borrowing | Lesefunktionen mit `&str` schreiben. |
| 3 | Mutation | `&mut String` gezielt einsetzen. |
| 4 | Slices | Funktionen mit `&[i32]` schreiben. |
| 5 | Fehlerbehandlung | `Option` statt `unwrap()` nutzen. |
| 6 | Rustlings | 5 Aufgaben lösen und Fehler notieren. |
| 7 | Mini-Projekt | Ein eigenes kleines CLI planen. |

## 23.8 Mentale Modelle & Deep Dive

### Lernschleife

```mermaid
flowchart LR
    A[Konzept lesen] --> B[Ohne Vorlage anwenden]
    B --> C[Compilerfeedback lesen]
    C --> D[Fehlerregel formulieren]
    D --> E[Variante schreiben]
    E --> B
```

### Lernportale

| Portal | Stärke | Beste Nutzung |
|---|---|---|
| Rustlings | Kleine Compilerübungen | Täglich 10 bis 20 Minuten. |
| Exercism | Aufgaben mit Community-Vergleich | Nach eigener Lösung andere Lösungen lesen. |
| The Rust Book | Offizielle Erklärung | Als Referenz und Vertiefung. |
| Kurs-mdBook | Lokales Nachschlagewerk | Begriffe und Kapitel gezielt suchen. |
| Rust by Example | Kompakte Beispiele | Syntaxvarianten schnell prüfen. |

### KI-Rollen

| Rolle | Guter Prompt | Risiko |
|---|---|---|
| Tutor | "Stellen Sie mir Fragen zu Borrowing." | Zu oberflächlich, wenn kein Niveau genannt wird. |
| Reviewer | "Bewerten Sie meine Lösung idiomatisch." | Vorschläge blind übernehmen. |
| Fehlerdiagnose | "Erklären Sie E0382 anhand meines Codes." | Fehlenden Codekontext liefern. |
| Aufgabengenerator | "Erstellen Sie 3 Aufgaben ohne Lösung." | Zu große Aufgaben wählen. |

## 23.9 Drei praktische Übungen

### Übung 1: Leicht - Lernnotiz schreiben

Schreiben Sie nach einer Compilerfehlermeldung drei Sätze:

- Was wollte ich tun?
- Welche Regel habe ich verletzt?
- Welche Signatur oder Reihenfolge löst das Problem?

Lösungshinweis: Nutzen Sie immer die Fehlernummer, zum Beispiel `E0382`.

### Übung 2: Mittel - KI-Prompt verbessern

Schlechter Prompt:

```text
Fix meinen Rust-Code.
```

Schreiben Sie daraus einen präzisen Prompt mit:

- Lernstand;
- Code;
- Fehlermeldung;
- gewünschter Erklärungsform;
- Bitte um Hinweis vor fertiger Lösung.

Lösungshinweis: Bitten Sie die KI zuerst um Diagnose, nicht sofort um neuen Code.

### Übung 3: Schwer - Eigene Wochenroutine planen

Planen Sie sieben Tage Rust-Übung mit je:

- Thema;
- Mini-Aufgabe;
- erwarteter Compilerfehler oder Lernpunkt;
- Reflexionsfrage.

Lösungshinweis: Jede Einheit sollte in 20 bis 40 Minuten machbar sein.

## 23.10 Lernstrategie, Selbsteinschätzung & Merkzettel

### Cheat Sheet: Prompt-Vorlagen

```text
Ich lerne Rust auf Anfaengerniveau. Hier ist mein Code:
[Code]
Hier ist die Fehlermeldung:
[Fehler]
Bitte erklaeren Sie mir zuerst die verletzte Rust-Regel, dann den Speicherzustand,
und geben Sie erst danach einen minimalen Korrekturvorschlag.
```

```text
Erstellen Sie drei Rust-Uebungen zu [Thema].
Keine Loesung im ersten Schritt.
Geben Sie Anforderungen, Beispiel-Input, Beispiel-Output und je einen Hinweis.
```

### Active Recall

1. Warum ist Kopieren von Lösungen schlechter als aktives Abrufen?
2. Wie verwandeln Sie eine Compilerfehlermeldung in eine Lernnotiz?
3. Wann sollte KI keinen fertigen Code liefern?
4. Wie erkennen Sie Tutorial-Hölle?

### Feynman-Methode

Erklären Sie einer anderen Person in drei Sätzen, wie Sie Rust lernen: Aufgabe, Fehler, Reflexion.

### Gezielte Fehlerprovokation

Nehmen Sie eine funktionierende Lesefunktion und ändern Sie den Parameter von `&str` zu `String`. Beschreiben Sie, welcher Move entsteht.

### Selbsttest

Sie arbeiten strategisch, wenn Sie:

- täglich kleine Aufgaben lösen;
- Fehlernummern dokumentieren;
- KI nach Erklärungen statt nur nach Lösungen fragen;
- jede Woche ein eigenes Mini-Projekt beginnen.

## 23.11 Zusammenfassung

- Rust braucht aktive, kurze und regelmäßige Übung.
- Compilerfehler sind Lernmaterial.
- Rustlings und Exercism ergänzen das Lehrbuch durch Praxis.
- KI ist am wertvollsten als Tutor, Reviewer und Aufgabengenerator.
- Gute Prompts enthalten Kontext, Code, Fehlermeldung und Lernziel.
