## 2. Die Definition

* **Array (`[T; N]`)**: Ein homogener, sequentieller Datentyp mit einer festen Anzahl `N` von Elementen des Typs `T`. Die Größe `N` ist Teil des Typs (z. B. ist `[i32; 3]` ein anderer Typ als `[i32; 4]`) und muss zwingend zur Compilezeit feststehen. Arrays werden flach auf dem Stack alloziiert.
* **Tupel (`(T1, T2, T3, ...)`)**: Ein heterogener, strukturierter Datentyp, der eine feste Anzahl von Werten unterschiedlicher Typen in einer geordneten Sequenz zusammenfasst. Auch die Struktur eines Tupels ist nach seiner Definition unveränderlich.
* **Unit-Typ (`()`)**: Ein spezielles Tupel ohne Elemente. Es besitzt eine Größe von 0 Bytes und repräsentiert das Fehlen eines Werts (vergleichbar mit `void` in C/C++ oder Java).
* **Index**: Die ganzzahlige Position eines Elements innerhalb eines Arrays oder Tupels, beginnend bei `0` für das erste Element.

### Didaktische Analogien

> [!NOTE]
> **Die Pillendose für Arrays**:
> Stellen Sie sich eine wöchentliche Pillendose mit genau sieben nummerierten Fächern vor. Jedes Fach ist exakt gleich groß und kann nur Pillen desselben Typs aufnehmen (homogen). Sie können der Dose keine Fächer hinzufügen und keine entfernen (feste Größe). Wenn Sie auf ein Fach zugreifen wollen, das über den siebten Tag hinausgeht, greifen Sie ins Leere – Rust verhindert dies strikt.

> [!NOTE]
> **Das Postfach für Tupel**:
> Stellen Sie sich ein Postfach für ein Paket vor, das verschiedene Gegenstände enthält: Einen Brief (Text), einen Schlüssel (Ganzzahl) und eine Zugangskarte (Wahrheitswert). Die Gegenstände sind unterschiedlich geformt und haben unterschiedliche Bedeutungen (heterogen), sind aber fest in diesem einen Paket an Sie adressiert.

## 3. Das Problem & Die Motivation

In der Softwareentwicklung stehen Programmierer häufig vor der Aufgabe, logisch zusammengehörige Daten zu verwalten. Wenn wir beispielsweise die Temperaturen einer Arbeitswoche (fünf Tage) erfassen möchten, könnten wir einen Tag nach dem anderen in einzelnen Variablen speichern:

```rust
let temp_montag = 19.5;
let temp_dienstag = 20.1;
// ...
```

Dieser Ansatz skaliert nicht. Wir können diese Daten nicht in einer Schleife durchlaufen, sie nicht als geschlossene Einheit an Funktionen übergeben und keine mathematischen Operationen (wie die Berechnung des Mittelwerts) kompakt formulieren.

Für heterogene Daten (z. B. Name, Alter und Aktivitätsstatus eines Benutzers) gilt dasselbe. Einzelne Variablen verlieren ihre logische Zusammengehörigkeit:

```rust
let name = "Tobias";
let alter = 34;
let aktiv = true;
```

Wir benötigen Container, die diese Daten bündeln. 

### Warum nicht einfach dynamische Kollektionen wie Vektoren (`Vec<T>`) nutzen?
Vektoren sind dynamisch und können zur Laufzeit wachsen. Diese Flexibilität erkauft man sich jedoch mit System-Overhead:
1. **Heap-Allokation**: Vektoren speichern ihre Elemente auf dem Heap. Der Zugriff erfordert eine Indirektion (einen Zeiger auf dem Stack, der auf den Heap verweist). Heap-Allokationen erfordern komplexe Algorithmen des Betriebssystems zur Speicherverwaltung und sind um Größenordnungen langsamer als Stack-Operationen.
2. **Speicher-Overhead**: Ein Vektor benötigt auf dem Stack mindestens 24 Bytes (Pointer, Länge, Kapazität), selbst wenn er leer ist.
3. **Laufzeit-Indirektion**: Da die Daten auf dem Heap liegen, muss die CPU bei jedem Zugriff eine zusätzliche Speicheradresse auflösen, was Cache-Misses begünstigen kann.

Arrays und Tupel bieten hier die perfekte Lösung für Daten mit konstanter Struktur. Da ihre Größe zur Compilezeit feststeht, kann der Compiler sie direkt und ohne Indirektion flach auf dem Stack anordnen. Die Allokation ist extrem schnell, da lediglich der Stack-Pointer verschoben werden muss.

## 4. Der naive Versuch

Der folgende Code zeigt den naiven Versuch eines Programmierers, Temperaturen über ein Array einzulesen und basierend auf einer dynamischen Benutzereingabe (oder einem berechneten Index) einen Wert auszulesen. Da keine Validierung des Index stattfindet, führt ein falscher Index zu einem unkontrollierten Absturz des Programms zur Laufzeit.

```rust
use std::io;

fn main() {
    // Ein Array mit den gemessenen Temperaturen von Montag bis Freitag
    let temperaturen = [18.2, 19.5, 20.8, 17.4, 19.1];
    
    println!("Wir haben {} Temperaturen aufgezeichnet.", temperaturen.len());
    println!("Geben Sie den Tag als Index ein (0 für Montag bis 4 für Freitag):");

    let mut eingabe = String::new();
    io::stdin()
        .read_line(&mut eingabe)
        .expect("Fehler beim Lesen der Eingabe");

    // Parsen der Eingabe in eine Ganzzahl
    let index: usize = eingabe
        .trim()
        .parse()
        .expect("Bitte geben Sie eine gültige Zahl ein");

    // NAIVER VERSUCH: Direkter, ungeschützter Zugriff über den Index
    let ausgewaehlte_temp = temperaturen[index];

    println!("Die Temperatur an Index {} beträgt: {}°C", index, ausgewaehlte_temp);
}
```

## 5. Die Anatomie des Fehlers

### Das Verhalten bei Fehlanwendung
Wenn Sie dieses Programm ausführen und eine Zahl außerhalb des gültigen Bereichs (also `5` oder größer) eingeben, lässt sich das Programm zwar problemlos kompilieren, stürzt jedoch zur Laufzeit mit folgender Fehlermeldung (einer sogenannten *Panic*) ab:

```text
thread 'main' panicked at src/main.rs:21:29:
index out of bounds: the len is 5 but the index is 5
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
```

### Was passiert im Speicher?

Betrachten wir das Speicherlayout auf dem Stack während der Ausführung:

```text
       STACK-SPEICHER (Wachstum nach unten)
      +-----------------------------------------+
      | Variable      | Typ       | Wert        |
      +---------------+-----------+-------------+
      | temperaturen  | [f64; 5]  |             |
      |   [0]         | f64       | 18.2        |  <- Adresse: 0x7ffd..00
      |   [1]         | f64       | 19.5        |  <- Adresse: 0x7ffd..08
      |   [2]         | f64       | 20.8        |  <- Adresse: 0x7ffd..10
      |   [3]         | f64       | 17.4        |  <- Adresse: 0x7ffd..18
      |   [4]         | f64       | 19.1        |  <- Adresse: 0x7ffd..20
      +---------------+-----------+-------------+
      | index         | usize     | 5           |  <- Benutzereingabe
      +-----------------------------------------+
```

Ein `f64`-Wert belegt exakt 8 Bytes. Das Array `temperaturen` belegt somit als zusammenhängender Block `5 * 8 = 40` Bytes auf dem Stack. 

1. **Die Adressberechnung**: Wenn wir `temperaturen[index]` aufrufen, berechnet die CPU die physische Speicheradresse nach der Formel:
   $$\text{Zieladresse} = \text{Startadresse} + (\text{Index} \times \text{Größe des Datentyps})$$
   Für `index = 5` ergibt dies:
   $$\text{Zieladresse} = 0x7ffd..00 + (5 \times 8 \text{ Bytes}) = 0x7ffd..28$$
2. **Die Gefahr**: Die berechnete Adresse `0x7ffd..28` liegt außerhalb des alloziierten Speicherbereichs von `temperaturen`. Sie zeigt auf den Speicherbereich der nachfolgenden Variablen (`index`).
3. **Warum Rust eingreift**: In Programmiersprachen wie C oder C++ würde das System diese Adresse unbemerkt auslesen. Das führt entweder zu logisch falschen Werten (Information Leak) oder, falls auf geschützten Speicher zugegriffen wird, zu einem Segmentation Fault. In Rust überprüft der Compiler bzw. die Laufzeitumgebung bei jedem Indexzugriff über eckige Klammern die Bedingung:
   $$\text{Index} < \text{Länge des Arrays}$$
   Da `5 < 5` falsch ist, bricht Rust das Programm kontrolliert ab, um die Speichersicherheit des Gesamtsystems zu garantieren.

## 6. Die Lösung

Um diesen Laufzeitabsturz zu verhindern, wenden wir das **EVA-Prinzip** (Eingabe - Verarbeitung - Ausgabe) an und nutzen die sichere Methode `.get()`, die ein `Option<&T>` zurückgibt, anstatt des ungeschützten Index-Operators.

```rust
use std::io;

fn main() {
    // 1. EINGABE (Input)
    let temperaturen = [18.2, 19.5, 20.8, 17.4, 19.1];
    
    println!("Geben Sie den Tag als Index ein (0 bis 4):");
    let mut eingabe = String::new();
    io::stdin()
        .read_line(&mut eingabe)
        .expect("Fehler beim Lesen");

    let index: usize = match eingabe.trim().parse() {
        Ok(num) => num,
        Err(_) => {
            println!("Fehler: Bitte geben Sie eine positive Ganzzahl ein.");
            return;
        }
    };

    // 2. VERARBEITUNG (Processing) & AUSGABE (Output)
    // .get() gibt im Erfolgsfall Some(&Wert) zurück, andernfalls None.
    match temperaturen.get(index) {
        Some(&temp) => {
            println!("Erfolgreicher Zugriff!");
            println!("Die Temperatur an Index {} beträgt: {}°C", index, temp);
        }
        None => {
            println!("Fehler: Der Index {} liegt außerhalb des gültigen Bereichs (0 bis {}).", 
                     index, temperaturen.len() - 1);
        }
    }
}
```

### Erklärung nach dem EVA-Prinzip

1. **Eingabe (Input)**: Wir lesen den Index als Zeichenkette ein und parsen ihn sicher mittels `match` auf das `Result`-Objekt von `.parse()`. Fehlerhafte Eingaben (wie Buchstaben) werden abgefangen, ohne dass das Programm abstürzt.
2. **Verarbeitung (Processing)**: Wir übergeben den berechneten `usize`-Index an die Methode `.get()`. 
   * **Signatur**: `pub fn get<I>(&self, index: I) -> Option<&I::Output>`
   * Ist der Index gültig, wird die Referenz auf das Element in einen `Some`-Wrapper verpackt.
   * Ist der Index ungültig, gibt die Methode `None` zurück.
3. **Ausgabe (Output)**: Das Programm verzweigt über ein `match`-Konstrukt. Im Erfolgsfall wird der Wert dereferenziert und ausgegeben. Im Fehlerfall wird eine lesbare Fehlermeldung ausgegeben, und das Programm läuft stabil weiter.

## 7. Kleines Tutorial: Die Mini-Wetterstation

In diesem Tutorial erstellen wir eine kleine Anwendung für eine Wetterstation. Wir kombinieren Arrays (für die Speicherung von Temperaturmesswerten eines Tages) und Tupel (für die Aggregation von Wetterdaten wie Luftfeuchtigkeit, Windgeschwindigkeit und Ortsname).

### Schritt 1: Das Projekt anlegen
Erstellen Sie ein neues Cargo-Projekt in Ihrem Workspace:
```bash
cargo new weather_station --bin
```

### Schritt 2: Den Code implementieren
Ersetzen Sie den Inhalt von `src/main.rs` durch den folgenden Code:

```rust
/// Berechnet den Durchschnitt einer festen Anzahl von Messwerten.
/// 
/// **Eingabe (Input)**: Ein Array-Referenz `&[f64; 5]` (5 Messwerte)
/// **Verarbeitung (Processing)**: Summiert alle Werte und dividiert durch 5.0
/// **Ausgabe (Output)**: Der Mittelwert als `f64`
fn berechne_durchschnitt(messwerte: &[f64; 5]) -> f64 {
    let mut summe = 0.0;
    // Iteration über das Array
    for wert in messwerte.iter() {
        summe += wert;
    }
    summe / (messwerte.len() as f64)
}

/// Extrahiert die Daten aus einem Wetter-Tupel und gibt einen formatierten Bericht aus.
/// 
/// **Eingabe**: Ein Tupel bestehend aus (Ortsname, Luftfeuchtigkeit in %, Windgeschwindigkeit in km/h)
fn drucke_wetterbericht(daten: (&str, u32, f64)) {
    // Destrukturierung des Tupels
    let (ort, feuchtigkeit, wind) = daten;
    
    println!("--- Wetterbericht für {} ---", ort);
    println!("Luftfeuchtigkeit: {}%", feuchtigkeit);
    println!("Windgeschwindigkeit: {} km/h", wind);
}

fn main() {
    // 1. Array-Deklaration: 5 stündliche Messwerte
    let stunden_messungen: [f64; 5] = [12.5, 13.1, 14.5, 13.8, 12.0];

    // 2. Tupel-Deklaration: Heterogene Wetterdaten (Stadt, Luftfeuchtigkeit, Wind)
    let station_info: (&str, u32, f64) = ("Berlin-Tempelhof", 65, 12.4);

    // 3. Durchschnitt berechnen
    let schnitt = berechne_durchschnitt(&stunden_messungen);

    // 4. Bericht ausgeben
    drucke_wetterbericht(station_info);
    println!("Durchschnittliche Tagestemperatur: {:.2}°C", schnitt);

    // 5. Demonstration der Modifikation mit mut
    let mut aenderbare_messungen = stunden_messungen; // Kopie des Arrays auf den Stack
    aenderbare_messungen[0] = 15.0; // Änderung erlaubt, da 'mut' deklariert
    println!("Erster Messwert angepasst: {}°C", aenderbare_messungen[0]);
}
```

### Schritt 3: Ausführen und Validieren
Starten Sie das Programm mit Cargo:
```bash
cargo run
```
Sie sollten folgende Ausgabe sehen:
```text
--- Wetterbericht für Berlin-Tempelhof ---
Luftfeuchtigkeit: 65%
Windgeschwindigkeit: 12.4 km/h
Durchschnittliche Tagestemperatur: 13.18°C
Erster Messwert angepasst: 15°C
```

## 8. Mentale Modelle & Deep Dive

Um Rust auf Systemebene zu beherrschen, müssen wir verstehen, wie der Compiler diese Strukturen im physischen RAM anordnet und optimiert.

### 8.1 Arrays (`[T; N]`)

#### 8.1.1 Deklaration & Speicherstruktur

Arrays sind in Rust flach gepackte Sequenzen im Speicher. Deklarieren wir eine Variable `let arr = [10u8, 20u8, 30u8];`, sieht das Layout im Arbeitsspeicher wie folgt aus:

```text
       STACK-SPEICHER
      +---------------+-------------+
      | Adresse       | Wert (Byte) |
      +---------------+-------------+
      | 0x7ffd..00    | 10 (0x0A)   | -> arr[0]
      | 0x7ffd..01    | 20 (0x14)   | -> arr[1]
      | 0x7ffd..02    | 30 (0x1E)   | -> arr[2]
      +---------------+-------------+
```

##### Das Prinzip der Compilezeit-Größe
Da die Größe `N` im Typ verankert ist (z. B. `[i32; 1000]`), weiß der Compiler beim Übersetzen exakt, wie viel Speicherplatz im Stack-Frame der Funktion reserviert werden muss. Der Stack-Pointer wird beim Betreten der Funktion um diesen exakten Wert dekrementiert (bzw. inkrementiert, je nach CPU-Architektur). Es sind keine Systemaufrufe zur Laufzeit nötig.

##### Typinitialisierungsvarianten
Rust bietet zwei syntaktische Wege, ein Array zu initialisieren:
1. **Listen-Initialisierung**: Explizite Auflistung aller Werte:
   ```rust
   let a: [i32; 3] = [1, 2, 3];
   ```
2. **Wiederholungs-Initialisierung**: Ein Standardwert und die Anzahl der Wiederholungen, getrennt durch ein Semikolon:
   ```rust
   let b = [0; 500]; // Erstellt ein Array mit 500 Elementen, alle mit dem Wert 0 initialisiert.
   ```
   > [!IMPORTANT]
   > Die Wiederholungs-Initialisierung `[wert; N]` setzt voraus, dass der Typ des Werts das `Copy`-Trait implementiert oder es sich um einen konstanten Ausdruck handelt. Andernfalls könnte Rust die Werte nicht sicher im Speicher kopieren, ohne Ownership-Regeln zu verletzen.

##### Alignment und Padding bei Arrays
Arrays haben dasselbe Alignment (Ausrichtung im Speicher) wie ihr zugrundeliegender Elementtyp. Ein `[u8; 4]` hat ein Alignment von 1 Byte, während ein `[i64; 4]` ein Alignment von 8 Bytes besitzt. Das bedeutet, dass ein `[i64; 4]` im RAM an einer Speicheradresse liegen muss, die ohne Rest durch 8 teilbar ist. Dies ermöglicht es der CPU, die Werte über ihren Systembus in einem einzigen Taktzyklus einzulesen.

#### 8.1.2 Elementzugriff

Der Zugriff auf Array-Elemente kann auf zwei Wegen erfolgen:

##### 1. Index-Operator `arr[index]`
Dies ist der direkte Zugriff. Rust führt hierbei eine Laufzeitprüfung (Bounds Check) durch.
* **CPU-Overhead**: Bei jedem Zugriff wird eine zusätzliche Assembler-Instruktion zur Prüfung der Grenzen generiert (z. B. `cmp` und `jae` auf x86-Systemen).
* **Compiler-Optimierung (Bounds Check Elimination)**: Der LLVM-Compiler ist extrem intelligent. Wenn wir über eine feste Range iterieren, kann er beweisen, dass die Grenzen niemals überschritten werden. In diesem Fall eliminiert der Compiler die Laufzeitprüfungen vollständig:
  ```rust
  let arr = [10, 20, 30, 40, 50];
  // LLVM erkennt, dass 'i' nur Werte von 0 bis 4 annimmt.
  // Es werden KEINE Laufzeitprüfungen in der Schleife durchgeführt!
  for i in 0..5 {
      println!("{}", arr[i]); 
  }
  ```

##### 2. Sicherer Zugriff über `.get()` und `.get_mut()`
Diese Methoden geben ein `Option<&T>` bzw. `Option<&mut T>` zurück. Sie verhindern Abstürze vollständig und zwingen den Entwickler, den Fehlerfall explizit zu behandeln.

##### Multithreading und Arrays
Arrays implementieren die Auto-Traits `Send` und `Sync`, sofern der Elementtyp `T` diese implementiert.
* `Send`: Das Array kann an einen anderen Thread übertragen werden.
* `Sync`: Mehrere Threads können gleichzeitig über unveränderliche Referenzen (`&[T; N]`) auf das Array zugreifen.
Da ein Array flach auf dem Stack liegt, erfordert das Übertragen an einen anderen Thread eine Kopie der Daten, es sei denn, das Array wurde in ein intelligentes Zeiger-Konstrukt wie `Arc` oder einen Heap-Pointer (`Box`) verpackt.

### 8.2 Tupel (`(T1, T2, ...)`)

#### 8.2.1 Heterogene Strukturen

Ein Tupel fasst Typen unterschiedlicher Größe und Ausrichtung zusammen. Im Gegensatz zu Arrays gibt es bei Tupeln keine Garantie über die physische Anordnung der Felder im Speicher.

##### Das Phänomen des Field Reordering
Betrachten wir das Tupel `let t: (u8, i32, u8) = (1, 100, 2);`.
* Ein `u8` benötigt 1 Byte (Alignment: 1).
* Ein `i32` benötigt 4 Bytes (Alignment: 4).

Würde der Compiler die Felder strikt in der Reihenfolge der Deklaration im Speicher ablegen, sähe das Layout so aus:

```text
       NAIVES LAYOUT (Größe: 12 Bytes)
      +------+------+------+------+------+------+------+------+------+------+------+------+
      | u8   | Padding (3 Bytes)  | i32 (4 Bytes)             | u8   | Padding (3 Bytes)  |
      +------+------+------+------+------+------+------+------+------+------+------+------+
      | 0x01 | 0x00 | 0x00 | 0x00 | 0x00 | 0x00 | 0x00 | 0x64 | 0x02 | 0x00 | 0x00 | 0x00 |
      +------+------+------+------+------+------+------+------+------+------+------+------+
```

Um den Speicherplatz optimal auszunutzen, ordnet der Rust-Compiler die Felder im Speicher neu an (**Field Reordering**). Er sortiert sie absteigend nach ihrem Alignment-Bedarf. Das tatsächliche Layout im RAM sieht daher so aus:

```text
       OPTIMIERTES LAYOUT (Größe: 8 Bytes)
      +---------------------------+------+------+---------------------+
      | i32 (4 Bytes)             | u8   | u8   | Padding (2 Bytes)   |
      +---------------------------+------+------+---------------------+
      | 0x00 | 0x00 | 0x00 | 0x64 | 0x01 | 0x02 | 0x00 | 0x00         |
      +---------------------------+------+------+---------------------+
```

Durch diese Optimierung spart Rust 4 Bytes Speicherplatz auf dem Stack ein. 

> [!WARNING]
> Verlassen Sie sich niemals auf die physische Reihenfolge der Felder in einem Tupel im Speicher. Wenn Sie ein definiertes Speicherlayout für die Interoperabilität mit C-Bibliotheken benötigen, verwenden Sie stattdessen ein Struct mit dem Attribut `#[repr(C)]`.

##### Der Unit-Typ `()`
Das leere Tupel `()` ist ein fundamentaler Typ in Rust.
* **Größe**: `std::mem::size_of::<()>() == 0`
* **Zweck**: Funktionen, die keinen expliziten Rückgabetyp definieren, geben implizit den Unit-Typ zurück. Er signalisiert dem Compiler: "Diese Operation wurde erfolgreich abgeschlossen, liefert aber keinen nutzbaren Datenwert zurück."

#### 8.2.2 Elementzugriff

Auf Tupel-Elemente kann nicht mit eckigen Klammern und einer dynamischen Variable zugegriffen werden (`tup[i]` ist ungültig). Da die Elemente unterschiedliche Typen haben können, muss der Typ jedes Zugriffs zur Compilezeit feststehen.

##### 1. Punkt-Notation (Statische Indexierung)
Der Zugriff erfolgt über `.0`, `.1`, `.2` etc. Der Compiler kennt den Typ jedes Feldes an dieser Position und prüft den Zugriff streng zur Compilezeit. Ein Zugriff auf `.3` bei einem 3er-Tupel führt zu einem sofortigen Compiler-Fehler.

##### 2. Destrukturierung via Pattern Matching
Dies ist der eleganteste und idiomatischste Weg, um an die Werte eines Tupels zu gelangen.

```rust
let person = ("Anna", 28, true);

// Komplettes Entpacken
let (name, alter, ist_aktiv) = person;

// Ignorieren ungenutzter Felder mit dem Unterstrich (_)
let (name, _, _) = person;

// Ignorieren des Rests mit der Punkt-Punkt-Syntax (..)
let (name, ..) = person;
```

##### Tupel als Rückgabewerte
Da Rust-Funktionen standardmäßig nur einen Wert zurückgeben können, sind Tupel das ideale Werkzeug, um mehrere Werte ad hoc und ohne die Deklaration eines eigenen Structs zurückzugeben:

```rust
fn dividiere(dividend: i32, divisor: i32) -> (i32, i32) {
    let quotient = dividend / divisor;
    let rest = dividend % divisor;
    (quotient, rest) // Rückgabe als Tupel
}
```

## Exhaustive API-Referenz (Arrays & Slices)

Da Arrays implizit zu Slices coercen (`Deref`-Coercion zu `[T]`), stehen Ihnen auf Arrays fast alle Methoden von Slices zur Verfügung. Nachfolgend finden Sie eine vollständige Übersicht über die wichtigsten Standardbibliotheksmethoden.

### 1. `len`
* **Signatur**: `pub const fn len(&self) -> usize`
* **Parameter**: `&self` (unveränderliche Referenz)
* **Rückgabetyp**: `usize` (die Anzahl der Elemente)
* **Sicherheitsaspekte & Panics**: Keine. Läuft immer sicher.
* **Beispiel**:
  ```rust
  let arr = [1, 2, 3];
  assert_eq!(arr.len(), 3);
  ```

### 2. `is_empty`
* **Signatur**: `pub const fn is_empty(&self) -> bool`
* **Parameter**: `&self`
* **Rückgabetyp**: `bool` (`true` wenn die Länge 0 ist, sonst `false`)
* **Sicherheitsaspekte & Panics**: Keine.
* **Beispiel**:
  ```rust
  let arr: [i32; 0] = [];
  assert!(arr.is_empty());
  ```

### 3. `first`
* **Signatur**: `pub const fn first(&self) -> Option<&T>`
* **Parameter**: `&self`
* **Rückgabetyp**: `Option<&T>` (Referenz auf das erste Element)
* **Sicherheitsaspekte & Panics**: Keine. Gibt bei leeren Slices `None` zurück.
* **Beispiel**:
  ```rust
  let arr = [10, 20, 30];
  assert_eq!(arr.first(), Some(&10));
  ```

### 4. `first_mut`
* **Signatur**: `pub fn first_mut(&mut self) -> Option<&mut T>`
* **Parameter**: `&mut self` (veränderbare Referenz)
* **Rückgabetyp**: `Option<&mut T>` (veränderbare Referenz auf das erste Element)
* **Sicherheitsaspekte & Panics**: Keine.
* **Beispiel**:
  ```rust
  let mut arr = [10, 20, 30];
  if let Some(first) = arr.first_mut() {
      *first = 99;
  }
  assert_eq!(arr[0], 99);
  ```

### 5. `last`
* **Signatur**: `pub const fn last(&self) -> Option<&T>`
* **Parameter**: `&self`
* **Rückgabetyp**: `Option<&T>` (Referenz auf das letzte Element)
* **Sicherheitsaspekte & Panics**: Keine.
* **Beispiel**:
  ```rust
  let arr = [10, 20, 30];
  assert_eq!(arr.last(), Some(&30));
  ```

### 6. `last_mut`
* **Signatur**: `pub fn last_mut(&mut self) -> Option<&mut T>`
* **Parameter**: `&mut self`
* **Rückgabetyp**: `Option<&mut T>` (veränderbare Referenz auf das letzte Element)
* **Sicherheitsaspekte & Panics**: Keine.
* **Beispiel**:
  ```rust
  let mut arr = [10, 20, 30];
  if let Some(last) = arr.last_mut() {
      *last = 99;
  }
  assert_eq!(arr[2], 99);
  ```

### 7. `get`
* **Signatur**: `pub fn get<I>(&self, index: I) -> Option<&I::Output> where I: SliceIndex<[T]>`
* **Parameter**: `index` (ein passender Index, z. B. `usize` oder eine Range wie `1..3`)
* **Rückgabetyp**: `Option<&T>` (bzw. Referenz auf das Teilschnitt-Slice)
* **Sicherheitsaspekte & Panics**: Keine.
* **Beispiel**:
  ```rust
  let arr = [10, 20, 30];
  assert_eq!(arr.get(1), Some(&20));
  assert_eq!(arr.get(5), None);
  ```

### 8. `get_mut`
* **Signatur**: `pub fn get_mut<I>(&mut self, index: I) -> Option<&mut I::Output> where I: SliceIndex<[T]>`
* **Parameter**: `index`
* **Rückgabetyp**: `Option<&mut T>`
* **Sicherheitsaspekte & Panics**: Keine.
* **Beispiel**:
  ```rust
  let mut arr = [10, 20, 30];
  if let Some(val) = arr.get_mut(1) {
      *val = 42;
  }
  assert_eq!(arr[1], 42);
  ```

### 9. `map` (Exklusiv für `[T; N]`)
* **Signatur**: `pub fn map<F, U>(self, f: F) -> [U; N] where F: FnMut(T) -> U`
* **Parameter**: `self` (Besitzübernahme des Arrays), `f` (Transformationsfunktion)
* **Rückgabetyp**: Ein neues Array `[U; N]` mit transformierten Werten
* **Sicherheitsaspekte & Panics**: Keine, außer die übergebene Closure `f` panickt.
* **Beispiel**:
  ```rust
  let arr = [1, 2, 3];
  let doubled = arr.map(|x| x * 2);
  assert_eq!(doubled, [2, 4, 6]);
  ```

### 10. `contains`
* **Signatur**: `pub fn contains(&self, x: &T) -> bool where T: PartialEq`
* **Parameter**: `x` (Referenz auf den gesuchten Wert)
* **Rückgabetyp**: `bool` (`true` wenn gefunden, sonst `false`)
* **Sicherheitsaspekte & Panics**: Keine.
* **Beispiel**:
  ```rust
  let arr = [1, 2, 3];
  assert!(arr.contains(&2));
  ```

### 11. `starts_with`
* **Signatur**: `pub fn starts_with(&self, needle: &[T]) -> bool where T: PartialEq`
* **Parameter**: `needle` (Slice-Referenz der gesuchten Startsequenz)
* **Rückgabetyp**: `bool`
* **Sicherheitsaspekte & Panics**: Keine.
* **Beispiel**:
  ```rust

  assert!(arr.starts_with(&[1, 2]));
  ```

### 12. `ends_with`
* **Signatur**: `pub fn ends_with(&self, needle: &[T]) -> bool where T: PartialEq`
* **Parameter**: `needle`
* **Rückgabetyp**: `bool`
* **Sicherheitsaspekte & Panics**: Keine.
* **Beispiel**:
  ```rust
  let arr = [1, 2, 3, 4];
  assert!(arr.ends_with(&[3, 4]));
  ```

### 13. `binary_search`
* **Signatur**: `pub fn binary_search(&self, x: &T) -> Result<usize, usize> where T: Ord`
* **Parameter**: `x` (Gesuchtes Element). Setzt ein sortiertes Array voraus!
* **Rückgabetyp**: `Result<usize, usize>` (`Ok(Index)` wenn gefunden, `Err(InsertIndex)` wenn nicht gefunden)
* **Sicherheitsaspekte & Panics**: Keine.
* **Beispiel**:
  ```rust

  assert_eq!(arr.binary_search(&30), Ok(2));
  ```

### 14. `sort`
* **Signatur**: `pub fn sort(&mut self) where T: Ord`
* **Parameter**: `&mut self`
* **Rückgabetyp**: `()` (Sortierung erfolgt In-Place, stabil)
* **Sicherheitsaspekte & Panics**: Keine.
* **Beispiel**:
  ```rust
  let mut arr = [3, 1, 2];
  arr.sort();
  assert_eq!(arr, [1, 2, 3]);
  ```

### 15. `sort_unstable`
* **Signatur**: `pub fn sort_unstable(&mut self) where T: Ord`
* **Parameter**: `&mut self`
* **Rückgabetyp**: `()` (In-Place, instabil aber meist schneller, alloziert keinen Hilfsspeicher)
* **Sicherheitsaspekte & Panics**: Keine.
* **Beispiel**:
  ```rust
  let mut arr = [3, 1, 2];
  arr.sort_unstable();
  assert_eq!(arr, [1, 2, 3]);
  ```

### 16. `reverse`
* **Signatur**: `pub fn reverse(&mut self)`
* **Parameter**: `&mut self`
* **Rückgabetyp**: `()` (Kehrt die Reihenfolge In-Place um)
* **Sicherheitsaspekte & Panics**: Keine.
* **Beispiel**:
  ```rust
  let mut arr = [1, 2, 3];
  arr.reverse();
  assert_eq!(arr, [3, 2, 1]);
  ```

### 17. `rotate_left`
* **Signatur**: `pub fn rotate_left(&mut self, mid: usize)`
* **Parameter**: `mid` (Rotationspunkt)
* **Rückgabetyp**: `()` (Rotiert Elemente nach links)
* **Sicherheitsaspekte & Panics**: Panickt, wenn `mid > len`.
* **Beispiel**:
  ```rust
  let mut arr = [1, 2, 3, 4, 5];
  arr.rotate_left(2);
  assert_eq!(arr, [3, 4, 5, 1, 2]);
  ```

### 18. `rotate_right`
* **Signatur**: `pub fn rotate_right(&mut self, k: usize)`
* **Parameter**: `k` (Anzahl der Schritte nach rechts)
* **Rückgabetyp**: `()`
* **Sicherheitsaspekte & Panics**: Panickt, wenn `k > len`.
* **Beispiel**:
  ```rust
  let mut arr = [1, 2, 3, 4, 5];
  arr.rotate_right(2);
  assert_eq!(arr, [4, 5, 1, 2, 3]);
  ```

### 19. `swap`
* **Signatur**: `pub fn swap(&mut self, a: usize, b: usize)`
* **Parameter**: `a` und `b` (Die zu tauschenden Indizes)
* **Rückgabetyp**: `()`
* **Sicherheitsaspekte & Panics**: Panickt, wenn `a` oder `b` außerhalb der Grenzen liegen.
* **Beispiel**:
  ```rust
  let mut arr = [10, 20, 30];
  arr.swap(0, 2);
  assert_eq!(arr, [30, 20, 10]);
  ```

### 20. `fill`
* **Signatur**: `pub fn fill(&mut self, value: T) where T: Clone`
* **Parameter**: `value` (Der Wert, mit dem das Array gefüllt werden soll)
* **Rückgabetyp**: `()`
* **Sicherheitsaspekte & Panics**: Keine.
* **Beispiel**:
  ```rust

  assert_eq!(arr, [9, 9, 9, 9]);
  ```

### 21. `fill_with`
* **Signatur**: `pub fn fill_with<F>(&mut self, f: F) where F: FnMut() -> T`
* **Parameter**: `f` (Eine Generator-Funktion/Closure)
* **Rückgabetyp**: `()`

* **Beispiel**:


### 22. `iter`
* **Signatur**: `pub fn iter(&self) -> Iter<'_, T>`
* **Parameter**: `&self`

* **Signatur**: `pub fn iter_mut(&mut self) -> IterMut<'_, T>`

### 24. `split_at`
* **Signatur**: `pub fn split_at(&self, mid: usize) -> (&[T], &[T])`
* **Parameter**: `mid` (Index, an dem gesplittet werden soll)
* **Rückgabetyp**: Ein Tupel aus zwei unveränderlichen Slice-Referenzen
* **Sicherheitsaspekte & Panics**: Panickt, wenn `mid > len`.
* **Beispiel**:

### 25. `split_at_mut`
* **Signatur**: `pub fn split_at_mut(&mut self, mid: usize) -> (&mut [T], &mut [T])`
* **Parameter**: `mid`

* **Sicherheitsaspekte & Panics**: Panickt, wenn `mid > len`.

### 26. `windows`
* **Signatur**: `pub fn windows(&self, size: usize) -> Windows<'_, T>`

## 10. Lernstrategie, Selbsteinschätzung & Merkzettel

### Spickzettel (Cheat Sheet)

| Struktur | Typ-Syntax | Initialisierungsbeispiel | Zugriffsmethode | Speicherort | Flexibilität |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Array** | `[T; N]` | `[10, 20, 30]` oder `[0; 10]` | `arr[0]` (unsicher), `arr.get(0)` (sicher) | Stack (flach) | Homogen, feste Größe |

| **Unit-Typ** | `()` | `()` | - | - (0 Bytes) | Repräsentiert "Nichts" |

## 11. Zusammenfassung

* **Arrays (`[T; N]`)** bieten eine extrem performante, homogene Speicherung auf dem Stack. Ihre Größe ist unveränderlicher Bestandteil ihres Typs.
* **Tupel (`(T1, T2, ...)`)** erlauben es, heterogene Daten flexibel und ohne Namenszwang zu gruppieren. Sie werden häufig für Mehrfach-Rückgaben aus Funktionen verwendet.
* **Bounds Checking** ist Rusts Sicherheitsnetz bei Array-Indexzugriffen. Es verhindert Speicherzugriffsfehler zur Laufzeit durch kontrolliertes Panik-Verhalten.
* **Sichere Alternativen** wie die Methode `.get()` liefern ein `Option<&T>` zurück und sollten bei dynamischen Indizes immer dem direkten Index-Operator vorgezogen werden.
* **Compiler-Optimierungen** wie *Field Reordering* (bei Tupeln zur Reduzierung von Padding) und *Bounds Check Elimination* (bei Arrays durch LLVM) sorgen dafür, dass Rust-Code trotz maximaler Sicherheit die Performance von handoptimiertem C++ erreicht.
