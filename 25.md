# Kapitel 25: Der Slice-Typ (Slices)

> [!IMPORTANT]
> Slices verbinden Borrowing mit praktischer Datenverarbeitung. Sie sind der Grund, warum Rust-Funktionen oft `&str` statt `&String` und `&[T]` statt `&Vec<T>` annehmen.

## 25.1 Lernziele & Lernplan

Nach diesem Kapitel können Sie:

- `&str`, `&[T]` und `&mut [T]` definieren und korrekt verwenden;
- erklären, warum Slices Fat Pointer aus Adresse und Länge sind;

- Index- und Borrowing-Fehler bei Slices analysieren;
- entscheiden, wann Slices flexibler sind als konkrete Container wie `String` oder `Vec<T>`.

## 25.2 Die Definition

Ein **Slice** ist eine nicht besitzende Sicht auf eine zusammenhängende Sequenz von Elementen. Er speichert keinen eigenen Inhalt, sondern verweist auf vorhandene Daten.

Slice-Formen:

| Typ | Bedeutung |
|---|---|
| `&str` | Geliehene Sicht auf gültige UTF-8-Textbytes. |
| `&[T]` | Geliehene unveränderliche Sicht auf Elemente vom Typ `T`. |
| `&mut [T]` | Geliehene veränderliche Sicht auf Elemente vom Typ `T`. |

Ein Slice ist ein Fat Pointer:

```text
&[T] = ptr + len
&str = ptr + len
```

Auf einer 64-Bit-Plattform sind das typischerweise 16 Bytes: 8 Bytes Adresse und 8 Bytes Länge.

## 25.3 Das Problem & die Motivation

Ohne Slices geben Funktionen oft lose Indizes zurück. Diese Indizes können später nicht mehr zum Datenzustand passen.

Beispielproblem: erstes Wort in einem String finden.

```rust
fn erstes_wort_index(text: &String) -> usize {
    let bytes = text.as_bytes();

    for (index, &byte) in bytes.iter().enumerate() {
        if byte == b' ' {
            return index;
        }
    }

    text.len()
}
```

Die Funktion gibt eine Zahl zurück. Diese Zahl ist aber nicht an den String gebunden. Wenn der String danach verändert wird, kann der Index fachlich ungültig werden.

> [!NOTE]
> Ein Slice koppelt Daten und Bereich. Ein loser Index ist nur eine Zahl.

## 25.4 Der naive Versuch

```rust
fn erstes_wort_index(text: &String) -> usize {
    let bytes = text.as_bytes();

    for (index, &byte) in bytes.iter().enumerate() {
        if byte == b' ' {
            return index;
        }
    }

    text.len()
}

fn main() {
    let mut text = String::from("Rust lernen");
    let ende = erstes_wort_index(&text);

    text.clear();

    println!("Erstes Wort endet bei Byte {ende}");
    println!("Erstes Wort: {}", &text[0..ende]);
}
```

Zeile-für-Zeile:

| Zeile | Erklärung |
|---|---|
| `erstes_wort_index(&text)` | Es wird nur ein Index berechnet. |
| `text.clear()` | Der String wird geleert; der Heap-Inhalt ändert sich. |
| `&text[0..ende]` | Der alte Index wird auf den neuen, leeren Text angewandt. |
| Ergebnis | Das Programm panikt zur Laufzeit. |

EVA:

| Phase | Beschreibung |
|---|---|
| Eingabe | Eine Referenz auf einen `String`. |
| Verarbeitung | Suche nach Leerzeichen als Byteposition. |
| Ausgabe | `usize`, nicht an den Eingabetext gebunden. |

## 25.5 Die Anatomie des Fehlers

Typische Laufzeitmeldung:

```text
thread 'main' panicked at 'byte index 4 is out of bounds of ``'
```

Der Compiler kann den logischen Zusammenhang zwischen `ende` und dem früheren Zustand von `text` nicht schützen, weil `ende` nur eine Zahl ist.

Speicherbild:

```text
Vor clear:
text -> "Rust lernen"
ende = 4

Nach clear:
text -> ""
ende = 4

Index 0..4 passt nicht mehr zum aktuellen Text.
```

## 25.6 Die Lösung

Die Funktion gibt einen Slice zurück:

```rust
fn erstes_wort(text: &str) -> &str {
    let bytes = text.as_bytes();

    for (index, &byte) in bytes.iter().enumerate() {
        if byte == b' ' {
            return &text[0..index];
        }
    }

    text
}

fn main() {
    let mut text = String::from("Rust lernen");
    let wort = erstes_wort(&text);

    println!("Erstes Wort: {wort}");

    text.clear();
    println!("Text nach clear: {text}");
}
```

Warum dies funktioniert:

- `wort` ist ein `&str`, der auf `text` verweist.
- Solange `wort` noch verwendet wird, darf `text` nicht veränderlich ausgeliehen werden.
- Nach der letzten Verwendung von `wort` darf `text.clear()` ausgeführt werden.

Wenn Sie `text.clear()` vor `println!("{wort}")` schieben, meldet Rust einen Borrowing-Konflikt.

Array- und Vektor-Slices:

```rust
fn summe(werte: &[i32]) -> i32 {
    werte.iter().sum()
}

fn main() {
    let array = [1, 2, 3, 4];
    let vec = vec![10, 20, 30, 40];

    println!("{}", summe(&array[1..3]));
    println!("{}", summe(&vec[..]));
}
```

EVA:

| Phase | Beschreibung |
|---|---|
| Eingabe | `&[i32]`, eine Sicht auf eine Folge von Zahlen. |
| Verarbeitung | Iterator liest jedes Element. |
| Ausgabe | `i32`, die berechnete Summe. |

## 25.7 Kleines Tutorial: Slices in Text und Zahlen

### Schritt 1: Pseudocode

```text
FUNKTION mittelwert(werte):
    wenn werte leer ist: None
    summe bilden
    durch laenge teilen
    Some(ergebnis)
```

### Schritt 2: Zahlenslice

```rust
fn mittelwert(werte: &[i32]) -> Option<f64> {
    if werte.is_empty() {
        return None;
    }

    let summe: i32 = werte.iter().sum();
    Some(summe as f64 / werte.len() as f64)
}

fn main() {
    let messwerte = vec![10, 20, 30, 40];
    let ausschnitt = &messwerte[1..3];

    println!("{:?}", mittelwert(ausschnitt));
    println!("{messwerte:?}");
}
```

### Schritt 3: Veränderlicher Slice

```rust
fn verdopple(werte: &mut [i32]) {
    for wert in werte {
        *wert *= 2;
    }
}

fn main() {
    let mut zahlen = [1, 2, 3, 4];
    verdopple(&mut zahlen[1..3]);
    println!("{zahlen:?}");
}
```

Analyse:

- `&mut zahlen[1..3]` leiht nur einen Teilbereich exklusiv aus.
- Die Schleife erhält veränderliche Referenzen auf die Elemente.
- `*wert *= 2` verändert den Wert hinter der Referenz.

## 25.8 Mentale Modelle & Deep Dive

### Fat Pointer

```text
Vec<i32> auf dem Stack:
+-----+-----+-----+
| ptr | len | cap |
+-----+-----+-----+
   |
   v
Heap: [10, 20, 30, 40]

Slice &vec[1..3]:
+-----+-----+
| ptr | len |
+-----+-----+
   |
   v
Heap:     [20, 30]
```

### UTF-8-Grenzen

`&str` muss immer gültiges UTF-8 sein. Deshalb dürfen String-Slices nur an gültigen Bytegrenzen entstehen:

```rust
fn main() {
    let text = "Gruesse";
    let teil = &text[0..2];
    println!("{teil}");
}
```

Bei Zeichen außerhalb ASCII können Bytepositionen überraschend sein. Nutzen Sie für benutzerorientierte Textverarbeitung Methoden wie `chars()`.

### Wichtige Slice-Methoden

| Methode | Zweck | Beispiel |
|---|---|---|
| `len()` | Länge abfragen | `werte.len()` |
| `is_empty()` | Leerprüfung | `werte.is_empty()` |
| `first()` | Erstes Element als `Option` | `werte.first()` |
| `last()` | Letztes Element als `Option` | `werte.last()` |
| `get(i)` | Sicherer Zugriff | `werte.get(2)` |
| `iter()` | Unveränderlich iterieren | `werte.iter()` |
| `iter_mut()` | Veränderlich iterieren | `werte.iter_mut()` |
| `contains(&x)` | Enthaltensein prüfen | `werte.contains(&3)` |
| `windows(n)` | Überlappende Fenster | `werte.windows(2)` |
| `chunks(n)` | Nicht überlappende Gruppen | `werte.chunks(2)` |
| `split_at(i)` | In zwei Slices teilen | `werte.split_at(2)` |

## 25.9 Drei praktische Übungen

### Übung 1: Leicht - Erstes Element

Schreiben Sie:

```rust
fn erstes(werte: &[i32]) -> Option<i32>
```

Anforderungen:

- `[]` ergibt `None`.
- `[8, 9]` ergibt `Some(8)`.
- Der Eingabevektor bleibt verwendbar.

Lösungshinweis: Nutzen Sie `first().copied()`.

### Übung 2: Mittel - Teilbereich summieren

Schreiben Sie:

```rust
fn summe_bereich(werte: &[i32], start: usize, ende: usize) -> Option<i32>
```

Anforderungen:

- Gültiger Bereich ergibt `Some(summe)`.
- Ungültiger Bereich ergibt `None`, keine Panic.

Lösungshinweis: Nutzen Sie `werte.get(start..ende)`.

### Übung 3: Schwer - Text sicher schneiden

Schreiben Sie:

```rust
fn erste_n_zeichen(text: &str, n: usize) -> String
```

Anforderungen:

- Schneiden Sie nach Zeichen, nicht nach Bytes.
- `"Gruesse", 3` ergibt `"Gru"`.
- Nicht-ASCII-Texte dürfen nicht paniken.

Lösungshinweis: Nutzen Sie `text.chars().take(n).collect()`.

## 25.10 Lernstrategie, Selbsteinschätzung & Merkzettel

### Cheat Sheet

| Ziel | Syntax |
|---|---|
| Ganzer String als Slice | `&text` oder `text.as_str()` |
| Teilstring | `&text[start..ende]` |
| Ganzer Vektor als Slice | `&werte[..]` |
| Teilbereich | `&werte[start..ende]` |
| Veränderlicher Teilbereich | `&mut werte[start..ende]` |
| Sicherer Zugriff | `werte.get(index)` |
| Sicherer Bereich | `werte.get(start..ende)` |

## 25.11 Zusammenfassung

- Slices sind geliehene Sichten auf zusammenhängende Daten.
- `&str` und `&[T]` bestehen aus Zeiger und Länge.
- Slices verhindern, dass Bereichsinformationen von Daten getrennt werden.
- Funktionen mit Slice-Parametern sind flexibler als Funktionen mit `&String` oder `&Vec<T>`.
- Direkte Indexierung kann paniken; `get` liefert sichere `Option`-Werte.
