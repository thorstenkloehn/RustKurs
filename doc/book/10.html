Rust-Videokurs für Anfänger

Kapitel 10: Funktionen

Funktionen sind die fundamentalen Bausteine der strukturierten Programmierung. Sie erlauben es Ihnen, Code in logische, wiederverwendbare und isolierte Einheiten zu unterteilen. In Rust sind Funktionen nicht nur ein Mittel zur Code-Organisation, sondern sie sind eng in das Typsystem und das Sicherheitsmodell der Sprache integriert. Dieses Kapitel vermittelt Ihnen ein tiefgehendes Verständnis dafür, wie Funktionen in Rust strukturiert sind, wie sich Anweisungen von Ausdrücken unterscheiden und wie der Compiler die Typsicherheit an den Grenzen von Funktionen garantiert.

2. Die Definition

  • Funktion (fn): Ein benannter, wiederverwendbarer Block von Anweisungen und Ausdrücken, der optional Eingabewerte (Parameter) akzeptiert, Berechnungen durchführt und einen Ausgabewert (Rückgabetyp) zurückgibt.
  • Funktionssignatur (Signaturdeklaration): Die äußere Schnittstelle einer Funktion. Sie definiert den Namen der Funktion, ihre Sichtbarkeit, die Liste der Parameter (inklusive ihrer Namen und Typen) sowie den Rückgabetyp. Sie stellt einen unveränderlichen Vertrag zwischen dem Aufrufer und der Funktion dar.
  • Parameter vs. Argument: Ein Parameter ist die in der Funktionssignatur deklarierte Variable (der Platzhalter). Ein Argument ist der konkrete Wert, der beim Aufrufen der Funktion an diesen Parameter übergeben wird.
  • Anweisung (Statement): Eine syntaktische Einheit, die eine Aktion ausführt, aber keinen Wert zurückgibt. In Rust enden Statements fast immer mit einem Semikolon ; (z. B. Variablenbindungen mit let).
  • Ausdruck (Expression): Eine syntaktische Einheit, die ausgewertet wird und einen Wert an das umgebende Programm liefert. Fast alles in Rust is ein Ausdruck, beispielsweise mathematische Operationen, Funktionsaufrufe oder Code-Blöcke.
  • Implizite Rückgabe (Tail Expression): Der Wert des letzten Ausdrucks in einem Code-Block (oder Funktionskörper), der kein Semikolon besitzt. Dieser Wert wird automatisch als Rückgabewert des Blocks oder der Funktion verwendet.
  • Unit-Typ (): Ein spezieller Typ in Rust, der genau einen Wert (ebenfalls ()) besitzt. Er drückt das Fehlen eines Werts aus (vergleichbar mit void in C/C++ oder Java). Jedes Statement in Rust wertet syntaktisch zum Unit-Typ () aus.

Alltagsnahe Metapher

[!NOTE] Die Backautomaten-Metapher: Stellen Sie sich eine Funktion wie einen programmierbaren Backautomaten vor.

  • Die Signatur des Automaten ist das Bedienfeld an der Außenseite: Sie zeigt genau an, welche Zutaten hineingeschüttet werden müssen (z. B. mehl_gramm: i32, wasser_ml: i32) und was am Ende herauskommt (-> Brot). Diese Schnittstelle ist unveränderlich. Sie können nicht einfach Kieselsteine hineinwerfen, da die Maschine dies physikalisch verhindert (Compilezeit-Prüfung).
  • Die Zutaten, die Sie tatsächlich hineinfüllen (z. B. 500 Gramm Weizenmehl und 300 ml Wasser), sind die Argumente.
  • Die internen mechanischen Schritte (Kneten, Gehenlassen, Backen) sind die Anweisungen (Statements). Sie tun etwas, aber Sie können kein fertiges Brot aus dem bloßen Kneten herausholen.
  • Der Moment, in dem die Klappe aufgeht und das fertige, warme Brot herausgleitet, ist die Expression (der Ausdruck). Das Brot wird an Sie ausgegeben. Wenn der Automat am Ende der Backzeit einfach stoppt und die Klappe geschlossen hält (weil ein Semikolon den Ausgabeprozess blockiert), haben Sie zwar Energie verbraucht, erhalten aber kein Ergebnis – die Maschine gibt Ihnen quasi ein leeres Blech (Unit-Typ ()) zurück.

3. Das Problem & Die Motivation

In den Anfängen der Softwareentwicklung (den 1950er und 1960er Jahren) wurden Programme oft linear geschrieben. Verzweigungen und Wiederholungen wurden durch unstrukturierte Sprungbefehle (wie GOTO auf Assembler-Ebene) realisiert. Dies führte rasch zu sogenanntem "Spaghetti-Code", der extrem schwer zu verstehen, zu warten und zu debuggen war. Edsger W. Dijkstra läutete 1968 mit seinem Aufsatz Go To Statement Considered Harmful eine Wende hin zur strukturierten Programmierung ein. Die Zerlegung von Programmen in modular abgrenzbare Subroutinen (Funktionen) wurde zum Standard.

Rust führt dieses Prinzip fort, verbindet es jedoch mit strengen Sicherheitsgarantien. In vielen dynamischen Programmiersprachen (wie Python oder JavaScript) können Funktionen beliebige Typen annehmen und zurückgeben:

// JavaScript: Keine Typsicherheit an der Funktionsgrenze
function berechne(x) {
    return x * 2;
}

Wenn Sie dieser JavaScript-Funktion eine Zeichenkette "hallo" übergeben, stürzt das Programm nicht ab, sondern liefert das verwirrende Ergebnis NaN (Not a Number) oder verhält sich unerwartet. Erst zur Laufzeit fallen solche Fehler auf – oft beim Endanwender.

Rust löst dieses Problem durch strikte Signaturdeklarationen. Der Compiler erzwingt, dass jeder Parameter und jeder Rückgabetyp explizit deklariert werden muss. Dies hat zwei fundamentale Vorteile:

  1. Module als isolierte Verträge: Der Compiler muss beim Übersetzen eines Funktionsaufrufs nicht den gesamten Körper der aufgerufenen Funktion analysieren. Er prüft lediglich, ob die übergebenen Argumente mit der Signatur übereinstimmen. Dies ermöglicht eine extrem schnelle, inkrementelle Kompilierung.
  2. Compilezeit-Garantien: Typfehler an Schnittstellen werden vollständig ausgeschlossen, bevor das Programm überhaupt ausgeführt wird.

Zusätzlich unterscheidet Rust streng zwischen Statements (Anweisungen) und Expressions (Ausdrücken). Während viele imperative Sprachen wie C oder Java fast ausschließlich auf Statements basieren, ist Rust eine ausdrucksorientierte Sprache. Nahezu jeder Code-Block ist ein Ausdruck, der einen Wert produzieren kann. Dies ermöglicht es Ihnen, prägnanten, funktionalen Code zu schreiben und Variablen direkt mit dem Ergebnis von Kontrollstrukturen zu initialisieren, ohne auf unsichere, temporäre Standardwerte angewiesen zu sein.

4. Der naive Versuch

Ein Anfänger möchte eine mathematische Hilfsfunktion schreiben, die das Quadrat einer übergebenen Ganzzahl berechnet. Da er aus anderen Sprachen (wie Java, C++ oder PHP) gewohnt ist, dass jede Zeile mit einem Semikolon enden muss, fügt er auch am Ende des Funktionskörpers ein Semikolon ein, obwohl er das Schlüsselwort return weggelassen hat.

Hier ist der fehlerhafte Code:

// Der naive Versuch eines quadratischen Berechners
fn quadrat_berechnen(zahl: i32) -> i32 {
    zahl * zahl; // Fehler! Das Semikolon unterdrückt die Wertabgabe.
}

fn main() {
    let ergebnis = quadrat_berechnen(5);
    println!("Das Quadrat von 5 ist: {}", ergebnis);
}

5. Die Anatomie des Fehlers

Das Compiler-Feedback

Wenn Sie versuchen, diesen Code mit cargo check oder cargo build zu kompilieren, verweigert der Compiler den Dienst und gibt folgende Fehlermeldung aus:

error[E0308]: mismatched types
 --> src/main.rs:2:36
  |
2 | fn quadrat_berechnen(zahl: i32) -> i32 {
  |    -----------------               ^^^ expected `i32`, found `()`
  |    |
  |    implicitly returns `()` as its body has no tail or `return` expression
3 |     zahl * zahl;
  |                - help: remove this semicolon to return this value

Der Blick hinter die Kulissen: Was passiert hier technisch?

  1. Die Auswertung der Signatur: Der Compiler liest die Signatur fn quadrat_berechnen(zahl: i32) -> i32. Damit geht die Funktion einen bindenden Vertrag ein: "Wenn Sie mir eine 32-Bit Ganzzahl (i32) übergeben, garantiere ich Ihnen, dass ich ebenfalls eine 32-Bit Ganzzahl (i32) zurückliefere."

  2. Die Umwandlung in ein Statement: Im Inneren der Funktion steht der Ausdruck zahl * zahl. Dieser berechnet das Quadrat. Da der Programmierer jedoch ein Semikolon ; an das Ende dieser Zeile setzt, transformiert er die Expression (den Ausdruck) in ein Statement (eine Anweisung).

  3. Der Unit-Typ () im Speicher: Statements in Rust haben per Definition keinen Rückgabewert. Um die syntaktische Konsistenz im Compiler zu wahren, gibt jedes Statement den Unit-Typ () zurück. Der Unit-Typ besitzt keine Daten und belegt 0 Bytes im Speicher. Er ist ein reines Signal für den Compiler: "Hier wurde eine Aktion ausgeführt, aber es gibt kein Ergebnis."

  4. Das Speicherlayout und CPU-Register: Wenn eine Funktion aufgerufen wird, legt das Betriebssystem einen Stack Frame (Stapelspeicherbereich) für diese Funktion an. In diesem Stack Frame werden lokale Variablen und Parameter gespeichert. Der Rückgabewert einer Funktion wird gemäß der System-ABI (Application Binary Interface) üblicherweise in einem bestimmten CPU-Register abgelegt (z. B. dem rax-Register bei x86_64-Prozessoren).

    • Bei einer korrekten Rückgabe schreibt die Funktion das Rechenergebnis in dieses Register, damit die aufrufende Funktion (main) es dort auslesen kann.
    • Durch das Semikolon signalisiert die Funktion dem Compiler, dass das Register nicht mit dem Ergebnis der Multiplikation befüllt werden soll. Die Funktion liefert stattdessen nichts (()) zurück.
    • Der Compiler stellt fest: Der Vertrag verlangt, dass ein i32-Wert aus dem Register gelesen wird. Die Funktion liefert aber das Register ungefüllt (bzw. ohne mathematischen Wert) zurück. Um zu verhindern, dass die main-Funktion "Müll" aus dem Register liest (was zu undefiniertem Verhalten oder Sicherheitslücken führen würde), bricht der Compiler den Kompilierungsprozess mit einem Typkonflikt (mismatched types) ab.

6. Die Lösung

Um den Fehler zu beheben, müssen wir den Funktionskörper so anpassen, dass der letzte Ausdruck tatsächlich ausgewertet und an den Aufrufer zurückgegeben wird. Dies geschieht in Rust idiomatisch, indem das Semikolon am Ende der letzten Zeile weggelassen wird. Alternativ kann das explizite Schlüsselwort return verwendet werden.

Der korrekte, lauffähige Code (Idiomatische Lösung)

// Idiomatische Lösung: Die letzte Zeile ist eine Expression ohne Semikolon
fn quadrat_berechnen(zahl: i32) -> i32 {
    zahl * zahl // Expression! Der Wert wird implizit zurückgegeben.
}

fn main() {
    let ergebnis = quadrat_berechnen(5);
    println!("Das Quadrat von 5 ist: {}", ergebnis);
}

Die alternative Lösung (Explizites Return)

// Alternative Lösung mit dem expliziten Schlüsselwort 'return'
fn quadrat_berechnen_explizit(zahl: i32) -> i32 {
    return zahl * zahl; // Mit return MUSS ein Semikolon gesetzt werden
}

fn main() {
    let ergebnis = quadrat_berechnen_explizit(5);
    println!("Das Quadrat von 5 ist (explizit): {}", ergebnis);
}

Zeile-für-Zeile-Erklärung nach dem EVA-Prinzip (Eingabe-Verarbeitung-Ausgabe)

Am Beispiel der idiomatischen Lösung (quadrat_berechnen):

  1. Eingabe (Input):
    • Syntax: zahl: i32 in der Parameterliste.
    • Besitzverhältnisse: Der Typ i32 implementiert das Copy-Trait. Das bedeutet, dass beim Aufruf quadrat_berechnen(5) der Wert 5 kopiert und direkt auf den Stack der Funktion gelegt wird. Es findet kein Besitzübergang (Move-Semantik) statt. Die Variable ergebnis in main besitzt nach dem Aufruf das Ergebnis unabhängig von den Berechnungen.
  2. Verarbeitung (Processing):
    • Syntax: zahl * zahl im Funktionskörper.
    • Logik: Der Prozessor holt den Wert aus dem Stack-Bereich der Funktion, führt die Multiplikation auf ALU-Ebene (Arithmetic Logic Unit) aus und hält das Ergebnis bereit.
  3. Ausgabe (Output):
    • Syntax: zahl * zahl ohne abschließendes Semikolon.
    • Logik: Da kein Semikolon folgt, wird dieser Wert als Tail Expression (Endausdruck) klassifiziert. Der Compiler generiert den Maschinencode so, dass das Ergebnis der Multiplikation im CPU-Rückgaberegister abgelegt und der Stack Frame von quadrat_berechnen sicher abgebaut wird. Die Kontrolle kehrt zur main-Funktion zurück, die den Wert aus dem Register liest und an ergebnis bindet.

7. Kleines Tutorial: CLI-Temperaturumrechner

In diesem Tutorial erstellen wir einen kleinen Kommandozeilen-Umrechner für physikalische Einheiten. Das Programm soll Celsius-Temperaturen in Fahrenheit und Kelvin konvertieren. Hierbei nutzen wir intensiv strukturierte Funktionen, explizite Signaturen, Block-Expressions und implizite Rückgaben.

Schritt 1: Die Signaturen deklarieren und leere Funktionsrümpfe anlegen

Wir beginnen mit dem Entwurf der Schnittstellen. Da wir Fließkommazahlen präzise umrechnen wollen, nutzen wir den Typ f64.

// Wir deklarieren die Funktionen zuerst mit dem Makro todo!().
// Dies erlaubt es uns, den Code zu kompilieren, ohne dass die Logik fertig ist.
fn celsius_in_fahrenheit(c: f64) -> f64 {
    todo!()
}

fn celsius_in_kelvin(c: f64) -> f64 {
    todo!()
}

Schritt 2: Die Konvertierungslogik mit impliziter Rückgabe implementieren

Nun füllen wir die Funktionen mit Leben. Wir nutzen die mathematischen Formeln und verzichten auf das Schlüsselwort return sowie auf Semikola am Ende, um den typischen Rust-Stil anzuwenden.

fn celsius_in_fahrenheit(c: f64) -> f64 {
    c * 1.8 + 32.0 // Implizite Rückgabe der Fahrenheit-Berechnung
}

fn celsius_in_kelvin(c: f64) -> f64 {
    c + 273.15 // Implizite Rückgabe der Kelvin-Berechnung
}

Schritt 3: Nutzung einer Block-Expression zur Datenaufbereitung

In der Hauptfunktion wollen wir die Ausgabe schön formatieren. Wir nutzen eine Block-Expression { ... }, um den Eingabewert vorzubereiten und zu validieren. Ein Block in Rust ist selbst ein Ausdruck und gibt den Wert seiner letzten Zeile zurück.

fn main() {
    let eingabe_celsius = 25.0;

    // Eine Block-Expression zur Kapselung von Hilfsberechnungen
    let status_meldung = {
        let ist_heiss = eingabe_celsius > 30.0;
        if ist_heiss {
            "Achtung: Es ist sehr warm!"
        } else {
            "Die Temperatur liegt im angenehmen Bereich."
        } // Die if-else-Expression gibt den String-Slice zurück
    }; // Das Semikolon beendet die Zuweisung (let-Statement)

    // Aufruf unserer Funktionen und Zuweisung der Ergebnisse
    let fahrenheit = celsius_in_fahrenheit(eingabe_celsius);
    let kelvin = celsius_in_kelvin(eingabe_celsius);

    // Ausgabe der Ergebnisse auf der Konsole
    println!("=== Temperaturumrechner ===");
    println!("Eingabe: {} °C", eingabe_celsius);
    println!("Fahrenheit: {} °F", fahrenheit);
    println!("Kelvin: {} K", kelvin);
    println!("Status: {}", status_meldung);
}

8. Mentale Modelle & Deep Dive

10.1 Strukturierung von Funktionen

10.1.1 Signaturdeklaration

Die Deklaration einer Funktion in Rust folgt einem strengen syntaktischen Schema. Jede Komponente der Signatur erfüllt eine wichtige Schutzfunktion für den Code.

Sichtbarkeit  Schlüsselwort  Name       Parameterliste (mit Typen)      Rückgabetyp
  │             │             │                 │                            │
  ▼             ▼             ▼                 ▼                            ▼
 pub           fn       addieren(a: i32, b: i32)                       ->   i32

  1. Sichtbarkeit (pub): Standardmäßig sind alle Funktionen in Rust privat. Das bedeutet, sie können nur innerhalb des Moduls aufgerufen werden, in dem sie definiert sind. Durch das Voranstellen von pub (public) wird die Funktion für andere Module und externe Crates sichtbar gemacht.

  2. Das Schlüsselwort fn: Es reserviert Speicher im Instruktionssegment des Programms und signalisiert dem Compiler den Beginn einer Funktionsdefinition.

  3. Der Funktionsname: Rust erzwingt die Namenskonvention snake_case (Kleinbuchstaben, Wörter getrennt durch Unterstriche). Falls Sie davon abweichen, erzeugt der Compiler eine Warnung (z. B. warn: function ... should have a snake_case name).

  4. Die Parameterliste: Jeder Parameter besteht aus einem Namen und einem Typ, getrennt durch einen Doppelpunkt (z. B. name: Typ). Mehrere Parameter werden durch Kommata getrennt.

    [!IMPORTANT] Das Verbot lokaler Typinferenz: Innerhalb von Funktionen kann Rust Typen oft automatisch ableiten (z. B. let x = 5; wird zu i32). An den Funktionsgrenzen (in der Parameterliste) ist dies jedoch streng untersagt. Sie müssen jeden Typ explizit hinschreiben. Dies stellt sicher, dass Funktionen als eigenständige Verträge fungieren und eine Code-Änderung in einer Funktion nicht unbemerkt zu Typverschiebungen in völlig anderen Teilen des Programms führt.

  5. Der Rückgabetyp (->): Der Rückgabetyp wird mit einem Pfeil deklariert. Wenn eine Funktion keinen Wert zurückgibt, wird der Pfeil samt Typ weggelassen. Syntaktisch gibt die Funktion dann den Unit-Typ () zurück. Folgende zwei Deklarationen sind für den Compiler absolut identisch:

    // Kurzschreibweise (üblich für Funktionen ohne Rückgabewert)
fn ausgabe_kurz() {
    println!("Hallo");
}

// Explizite Schreibweise (äquivalent zu oben)
fn ausgabe_explizit() -> () {
    println!("Hallo");
}
Divergierende Funktionen: Der Never-Type (!)

Ein besonderer Aspekt der Signaturdeklaration sind Funktionen, die niemals zum Aufrufer zurückkehren. Solche Funktionen werden als divergierende Funktionen bezeichnet. Ihr Rückgabetyp wird mit dem Ausrufezeichen ! (dem sogenannten Never-Type) deklariert.

// Diese Funktion kehrt nie zurück, da sie das Programm sofort beendet
fn fataler_fehler(nachricht: &str) -> ! {
    println!("Kritischer Systemfehler: {}", nachricht);
    panic!("Programmabbruch"); // crash des Threads, keine Rückkehr möglich
}

Divergierende Funktionen sind nützlich bei:

  • Unendlichen Kontrollschleifen (z. B. in Embedded Systems oder Webservern).
  • Funktionen, die das Programm absichtlich beenden (std::process::exit oder panic!).
Funktionszeiger (Der Typ fn)

Funktionen sind in Rust "First-Class Citizens". Das bedeutet, Sie können Funktionen wie normale Werte behandeln. Sie können Funktionen an Variablen zuweisen, sie als Argumente an andere Funktionen übergeben oder sie von Funktionen zurückgeben lassen. Der Typ einer Funktion wird durch ihre Signatur bestimmt und als kleingeschriebenes fn deklariert:

fn verdoppeln(x: i32) -> i32 {
    x * 2
}

fn main() {
    // Zuweisung einer Funktion an eine Variable.
    // Der Typ von 'operation' is: fn(i32) -> i32
    let operation: fn(i32) -> i32 = verdoppeln;

    let ergebnis = operation(10); // Aufruf über den Funktionszeiger
    println!("Ergebnis über Funktionszeiger: {}", ergebnis); // Ausgabe: 20
}

10.2 Anweisungen und Ausdrücke

10.2.1 Statements vs. Expressions

Das Programmiermodell von Rust unterscheidet präzise zwischen Statements (Anweisungen) und Expressions (Ausdrücken). Diese Unterscheidung ist der Schlüssel zur Eleganz und Ausdrucksstärke von Rust.

MerkmalStatement (Anweisung)Expression (Ausdruck)
ZweckFührt eine Aktion ausBerechnet einen Wert
RückgabewertKeiner (liefert immer den Unit-Typ ())Liefert das Ergebnis der Auswertung
SyntaxEndet meist mit einem Semikolon ;Endet nicht mit einem Semikolon
Beispielelet x = 5;, fn main() {}5 + 3, x * 2, celsius_in_kelvin(20.0)
Deklarations-Statements

Das häufigste Statement in Rust ist das Deklarations-Statement mittels let. Es bindet einen Namen an einen Wert:

let x = 5;

Da es sich hierbei um ein Statement handelt, gibt es keinen Wert zurück. Aus diesem Grund ist folgende Zuweisung in Rust syntaktisch verboten und führt zu einem Compilerfehler:

// In C/C++ oder Python ist dies erlaubt, in Rust jedoch illegal:
let y = (let x = 5);

Der Compiler bricht hier ab, weil das Statement let x = 5 keinen Wert liefert, den man an y binden könnte. Dies verhindert eine berüchtigte Fehlerklasse aus Sprachen wie C, bei der versehentlich eine Zuweisung statt eines Vergleichs in einer Bedingung geschrieben wird (z. B. if (x = 5) statt if (x == 5)). In Rust ist x = 5 ein Statement, liefert () zurück, und () kann nicht als Wahrheitswert (bool) in einer if-Bedingung verwendet werden.

Expression-Statements

Ein Expression-Statement ist ein Ausdruck, an den ein Semikolon angehängt wurde. Dadurch wird der Wert des Ausdrucks verworfen und der Typ zu () umgewandelt.

// Die mathematische Berechnung ist eine Expression:
5 + 3 // wertet zu 8 aus

// Durch das Semikolon wird sie zu einem Statement:
5 + 3; // wertet zu () aus (der Wert 8 wird verworfen)
Die Mächtigkeit von Block-Ausdrücken

In Rust ist ein mit geschweiften Klammern {} eingefasster Block ein Ausdruck. Das bedeutet, dass er einen Wert zurückgibt. Der Wert des Blocks entspricht dem Wert des letzten Ausdrucks innerhalb des Blocks.

fn main() {
    let y = {
        let x = 3;
        x + 1 // Expression! Kein Semikolon!
    }; // Das Semikolon schließt das let-Statement für y ab

    println!("y hat den Wert: {}", y); // Ausgabe: 4
}
  • Stack-Verhalten: Die Variable x ist nur innerhalb des Blocks { ... } gültig. Sobald der Block verlassen wird, wird der Speicher für x auf dem Stack freigegeben. Der Wert x + 1 (also 4) wird jedoch an y übergeben, welches im äußeren Stack Frame weiterlebt.

10.2.2 Implizite Rückgabe

Die implizite Rückgabe (auch Tail Expression genannt) ist ein zentrales Stilmittel in Rust. Sie basiert direkt auf der ausdrucksorientierten Natur der Sprache. Wenn der letzte Ausdruck im Rumpf einer Funktion kein Semikolon besitzt, wertet der Compiler diesen als den Rückgabewert der Funktion.

Der CPU- und Register-Ablauf (System-Schnittstelle)

Um zu verstehen, warum die implizite Rückgabe so effizient ist, müssen wir betrachten, wie der Prozessor (CPU) und der Speicher beim Aufruf einer Funktion zusammenarbeiten.

  1. Stack Frame Setup: Wenn main die Funktion quadrat_berechnen(5) aufruft:
    • Die CPU schiebt das Argument 5 in ein dafür vorgesehenes Register (z. B. rdi unter der x86_64 System-V-ABI) oder auf den Stack.
    • Die CPU führt den Befehl CALL aus. Dadurch wird die Rücksprungadresse (die Stelle in main, an der es nach der Funktion weitergehen soll) auf den Stack gelegt.
    • Ein neuer Stack Frame für quadrat_berechnen wird erstellt. Der Stack-Pointer (rsp) verschiebt sich nach unten, um Platz für lokale Berechnungen zu schaffen.
Stapelspeicher (Stack) bei Aufruf von 'quadrat_berechnen(5)':
┌────────────────────────────────────────────────────────┐
│ ... (Lokale Variablen von main)                        │
├────────────────────────────────────────────────────────┤
│ Rücksprungadresse (Adresse in main nach dem Call)      │ <-- Stack-Grenze main
├────────────────────────────────────────────────────────┤
│ Parameter 'zahl' (Wert: 5)                             │ <-- Stack Frame von
│ Lokaler Berechnungsbereich                             │     quadrat_berechnen
└────────────────────────────────────────────────────────┘
  1. Die Berechnung und das Rückgaberegister:
    • Die CPU berechnet 5 * 5 = 25.
    • Da es sich um eine Expression handelt (implizite Rückgabe), generiert der Rust-Compiler den Maschinencode so, dass das Ergebnis 25 direkt in das Akkumulator-Register (z. B. rax bei x86_64) geschrieben wird.
    • Es sind keine zusätzlichen Kopiervorgänge im RAM nötig.
  2. Der Stack Frame Abbau:
    • Die CPU führt den Befehl RET (Return) aus.
    • Der Stack Frame von quadrat_berechnen wird sofort ungültig gemacht (der Stack-Pointer rsp springt wieder nach oben).
    • Die CPU liest die Rücksprungadresse und setzt die Ausführung in main fort.
    • main liest den Wert 25 direkt aus dem rax-Register und weist ihn der Variablen ergebnis zu.
Wann ist ein explizites return notwendig?

Obwohl die implizite Rückgabe bevorzugt wird, gibt es Szenarien, in denen Sie das Schlüsselwort return explizit verwenden müssen. Dies betrifft vor allem sogenannte Early Returns (vorzeitige Rückgaben), bei denen eine Funktion aufgrund einer Bedingung abgebrochen werden soll, bevor das eigentliche Ende des Funktionskörpers erreicht ist.

fn dividieren(dividend: f64, divisor: f64) -> Result<f64, String> {
    // Vorzeitige Prüfung (Early Return)
    if divisor == 0.0 {
        return Err("Division durch Null ist mathematisch nicht definiert!".to_string());
    }

    // Wenn die Bedingung nicht zutrifft, läuft die Funktion normal weiter.
    // Am Ende nutzen wir wieder die implizite Rückgabe.
    Ok(dividend / divisor) 
}

Wenn Sie in Zeile 3 das return weglassen würden, würde der Compiler versuchen, den restlichen Code der Funktion auszuführen. Das würde zu logischen und syntaktischen Fehlern führen, da der Typ der if-Verzweigung nicht mit dem Rest der Funktion harmonieren würde.

Exhaustive API-Reference: Funktionen als Argumente in der Standardbibliothek

Da der Basistyp einer Funktion (fn) direkt keine Methoden besitzt, zeigt sich die Stärke von Funktionssignaturen und Funktionstypen vor allem dann, wenn sie als Parameter an Standardbibliotheksmethoden übergeben werden. Nachfolgend sind die wichtigsten Methoden aufgeführt, die Funktionen über die Traits Fn, FnMut oder FnOnce als Callbacks verarbeiten.

1. Option::map

  • Signatur: pub fn map<U, F>(self, f: F) -> Option<U> where F: FnOnce(T) -> U
  • Parameter:
    • self: Das Option<T>-Objekt, auf dem die Methode aufgerufen wird. Übergibt den Besitz (Ownership).
    • f: Eine Funktion (oder Closure), die den inneren Wert des Typs T konsumiert und einen neuen Wert des Typs U zurückgibt. Implementiert das Trait FnOnce, kann also nur einmal aufgerufen werden.
  • Rückgabetyp: Option<U>. Wenn das Original Some(T) war, wird Some(U) zurückgegeben. Wenn es None war, wird None zurückgegeben.
  • Panics: Keine direkten Panics durch die Methode selbst.
  • Minicode-Beispiel: 
    let wert: Option<i32> = Some(10);
let verdoppelt = wert.map(|x| x * 2); // Gibt Some(20) zurück
assert_eq!(verdoppelt, Some(20));

2. Iterator::filter

  • Signatur: pub fn filter<P>(self, predicate: P) -> Filter<Self, P> where Self: Sized, P: FnMut(&Self::Item) -> bool
  • Parameter:
    • self: Der Iterator, auf dem gearbeitet wird.
    • predicate: Eine Funktion, die eine Referenz auf das aktuelle Element (&Self::Item) entgegennimmt und einen Wahrheitswert (bool) zurückgibt. Implementiert FnMut, kann also interne Zustände verändern und mehrfach aufgerufen werden.
  • Rückgabetyp: Ein neuer Iterator vom Typ Filter<Self, P>, der nur die Elemente liefert, für die die Funktion true zurückgegeben hat.
  • Panics: Keine inhärenten Panics.
  • Minicode-Beispiel: 
    let zahlen = vec![1, 2, 3, 4, 5];
let gerade_zahlen: Vec<i32> = zahlen.into_iter().filter(|x| x % 2 == 0).collect();
assert_eq!(gerade_zahlen, vec![2, 4]);

3. Result::and_then

  • Signatur: pub fn and_then<U, F>(self, op: F) -> Result<U, E> where F: FnOnce(T) -> Result<U, E>
  • Parameter:
    • self: Das Result<T, E>-Objekt (Ownership).
    • op: Eine Funktion, die den inneren Erfolgswert T nimmt und ein neues Result<U, E> zurückgibt.
  • Rückgabetyp: Result<U, E>. Ermöglicht das Verketten von Operationen, die fehlschlagen können.
  • Panics: Keine.
  • Minicode-Beispiel: 
    let ok_wert: Result<i32, &str> = Ok(4);
let ergebnis = ok_wert.and_then(|x| Ok(x + 1));
assert_eq!(ergebnis, Ok(5));

4. std::thread::spawn

  • Signatur: pub fn spawn<F, T>(f: F) -> JoinHandle<T> where F: FnOnce() -> T, F: Send + 'static, T: Send + 'static
  • Parameter:
    • f: Eine parameterlose Funktion, die den Thread-Körper definiert. Sie gibt einen Wert des Typs T zurück. Sie muss die Traits Send (kann über Threadgrenzen verschickt werden) und 'static (lebt unbegrenzt lang) erfüllen.
  • Rückgabetyp: Ein JoinHandle<T>, mit dem auf das Ende des Threads gewartet und dessen Rückgabewert ausgelesen werden kann.
  • Panics: Kann panicken, wenn das Betriebssystem keinen neuen Thread erstellen kann (z. B. wegen Ressourcenerschöpfung).
  • Minicode-Beispiel: 
    use std::thread;
let handle = thread::spawn(|| {
    "Hallo aus dem Thread!"
});
assert_eq!(handle.join().unwrap(), "Hallo aus dem Thread!");

9. Drei praktische Übungen

Übung 1 (Leicht - Syntax festigen)

Aufgabe: Schreiben Sie eine Funktion zur Berechnung des Umfangs eines Kreises.

  • Anforderungen:
    • Funktionsname: kreis_umfang
    • Parameter: radius vom Typ f64
    • Rückgabetyp: f64
    • Nutzen Sie für die Kreiszahl Pi die Konstante std::f64::consts::PI.
    • Verwenden Sie die implizite Rückgabe (kein return, kein Semikolon am Ende).
  • Beispiel-Inputs/Outputs:
    • kreis_umfang(1.0) -> ca. 6.283185307179586
    • kreis_umfang(5.0) -> ca. 31.41592653589793
  • Lösungshinweis (Hint): Die mathematische Formel lautet: \( U = 2 \cdot \pi \cdot r \). Stellen Sie sicher, dass Sie die Konstante importieren oder mit ihrem vollen Pfad ansprechen.

Übung 2 (Mittel - Logik erweitern)

Aufgabe: Entwickeln Sie eine Funktion für einen Onlineshop, die den Endpreis eines Artikels nach Abzug eines Rabatts berechnet.

  • Anforderungen:
    • Funktionsname: berechne_rabattierten_preis
    • Parameter:
      • bruttopreis: f64
      • rabatt_prozent: f64 (z. B. 15.0 für 15 %)
      • mindestbestellwert: f64
    • Rückgabetyp: f64
    • Logik: Wenn der bruttopreis kleiner als der mindestbestellwert ist, darf kein Rabatt abgezogen werden (es wird der unveränderte Bruttopreis zurückgegeben). Nutzen Sie hierfür ein Early Return mit dem Schlüsselwort return. Wenn die Bedingung nicht zutrifft, berechnen Sie den Preis über eine Block-Expression mit impliziter Rückgabe.
  • Beispiel-Inputs/Outputs:
    • berechne_rabattierten_preis(100.0, 10.0, 50.0) -> 90.0 (Bruttopreis >= Mindestbestellwert, Rabatt wird gewährt)
    • berechne_rabattierten_preis(40.0, 10.0, 50.0) -> 40.0 (Bruttopreis < Mindestbestellwert, kein Rabatt gewährt)
  • Lösungshinweis (Hint): Prüfen Sie zuerst if bruttopreis < mindestbestellwert. Nutzen Sie in diesem Zweig ein explizites return bruttopreis;. Dahinter definieren Sie eine Variable let endpreis = { ... }; und führen dort die Rabattberechnung durch.

Übung 3 (Schwer - Transferleistung)

Aufgabe: Schreiben Sie einen extrem einfachen mathematischen Interpreter für Textbefehle.

  • Anforderungen:
    • Funktionsname: kommando_auswerten
    • Parameter:
      • operation: &str (erlaubte Werte: "add", "sub", "mul", "div")
      • wert_a: i32
      • wert_b: i32
    • Rückgabetyp: Result<i32, String>
    • Logik:
      • Nutzen Sie eine match-Struktur zur Unterscheidung der Operationen.
      • Bei der Division ("div") müssen Sie prüfen, ob der wert_b Null ist. Falls ja, geben Sie per Early Return einen Fehler im Err-Zweig zurück.
      • Alle Match-Arme müssen als Expressions (ohne Semikolon) den berechneten Wert im Ok-Zweig zurückgeben.
      • Unbekannte Operationen müssen als Err mit einer passenden Fehlermeldung abgefangen werden.
  • Beispiel-Inputs/Outputs:
    • kommando_auswerten("add", 10, 5) -> Ok(15)
    • kommando_auswerten("div", 10, 0) -> Err("Fehler: Division durch Null ist ungültig!".to_string())
    • kommando_auswerten("mod", 10, 5) -> Err("Fehler: Unbekannte Operation: mod".to_string())
  • Lösungshinweis (Hint): Das Grundgerüst der Funktion sieht so aus: 
    fn kommando_auswerten(operation: &str, wert_a: i32, wert_b: i32) -> Result<i32, String> {
    // Ihre Implementierung mit match und impliziten Rückgaben
}
    Denken Sie daran, dass jeder Match-Arm denselben Typ (Result<i32, String>) zurückliefern muss.

Active Recall (Selbsttestfragen)

  1. Frage: Warum führt die Zuweisung let x = (let y = 10); zu einem Compilerfehler?
    • Antwort: Weil let y = 10 ein Statement ist. Statements in Rust produzieren keinen Wert (bzw. werten zu () aus) und können daher nicht an andere Variablen zugewiesen werden.
  2. Frage: Was ist der Unterschied zwischen den Typen () und ! in einer Funktionssignatur?
    • Antwort: () (Unit-Typ) bedeutet, dass die Funktion erfolgreich fertiggestellt wird, aber keinen mathematischen Wert zurückgibt. ! (Never-Type) bedeutet, dass die Funktion niemals zum Aufrufer zurückkehrt (weil sie abstürzt oder in einer Endlosschleife läuft).
  3. Frage: Warum erzwingt Rust Typen in Funktionssignaturen, obwohl es innerhalb von Funktionen Typen automatisch ableiten kann?
    • Antwort: Um Funktionen als stabile, isolierte Verträge zu etablieren. Dies verhindert unbeabsichtigte Typfehler bei Code-Änderungen und beschleunigt die Kompilierungszeiten durch modulare Analyse drastisch.
  4. Frage: Wie unterscheidet sich eine Expression von einem Statement bezüglich des Semikolons?
    • Antwort: Ein Ausdruck (Expression) hat kein abschließendes Semikolon und gibt einen Wert ab. Hängt man ein Semikolon an einen Ausdruck an, wird er zu einem Statement und gibt nur noch den leeren Unit-Typ () zurück.

Die Feynman-Methode

11. Zusammenfassung

  • Strukturierte Bausteine: Funktionen (fn) kapseln Logik und machen sie wiederverwendbar. In Rust gelten strenge Namensregeln (snake_case) und standardmäßige Kapselung (Funktionen sind privat, sofern sie nicht mit pub markiert sind).
  • Vertragssicherheit: Funktionssignaturen müssen zwingend alle Parameter- und Rückgabetypen explizit deklarieren. Dies garantiert Typsicherheit an den Schnittstellen und ermöglicht inkrementelle Kompilierung.
  • Statements vs. Expressions: Rust ist ausdrucksorientiert. Während Statements (let x = 5;) Aktionen ausführen und keinen Wert liefern (Rückgabe ()), werten Expressions (5 + 3) zu konkreten Werten aus.
  • Implizite Rückgabe: Das Weglassen des Semikolons bei der letzten Zeile eines Blocks macht diese zur Tail Expression. Ihr Wert wird direkt als Rückgabewert des Blocks oder der Funktion verwendet.
  • Explizites Return: Das Schlüsselwort return wird in Rust fast ausschließlich für Early Returns verwendet, um eine Funktion bei Eintreffen einer Bedingung vorzeitig zu verlassen.
