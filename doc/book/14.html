Kapitel 14: Das Antigravity CLI – Arbeiten mit KI-Agenten & Subagenten

Stell dir vor, du hättest einen virtuellen Co-Entwickler direkt in deiner Konsole sitzen, der auf Knopfdruck Dateien erstellt, Code schreibt und Fehler sucht. Genau das ist das Antigravity CLI (aufrufbar über den Befehl agy).

In diesem Kapitel lernst du Schritt für Schritt, wie du das CLI installierst, es im Terminal steuerst und wie du durch Regeln bestimmst, was die KI-Agenten in deinem Projekt tun dürfen – und was nicht.

1. Was ist das Antigravity CLI?

Bevor wir loslegen, klären wir kurz ein paar grundlegende Begriffe:

  • CLI (Command Line Interface): Ein Programm, das du über Textbefehle im Terminal steuerst (auf Deutsch: Befehlszeilenschnittstelle).
  • KI-Agent: Ein intelligenter Assistent, der nicht nur deine Fragen beantwortet, sondern eigenständig Werkzeuge (Tools) benutzen kann, um z. B. Dateien zu lesen, zu editieren oder Befehle auszuführen.
  • Sandbox: Alle Befehle, die der Agent ausführt, laufen in einer abgesicherten Testumgebung (z. B. nsjail unter Linux). So kann der Agent dein echtes System nicht beschädigen.

2. Installation (Wie bekomme ich agy?)

Die Installation ist sehr einfach und erfordert nur einen einzigen Befehl in deinem Terminal:

  • Linux / macOS:

    curl -fsSL https://antigravity.google/cli/install.sh | bash

    Was passiert hier? Das Skript lädt das Programm herunter und installiert es im Ordner ~/.local/bin/agy, damit du es überall im Terminal aufrufen kannst.

  • Windows (PowerShell):

    irm https://antigravity.google/cli/install.ps1 | iex

3. Erste Schritte – Dein erster Prompt

Um das CLI zu starten, öffnest du dein Terminal, wechselst in dein Projektverzeichnis und tippst einfach agy ein:

cd /pfad/zu/deinem/projekt
agy

Der interaktive Modus (TUI)

Beim ersten Start öffnet sich ein kurzer Einrichtungsassistent (für Farben und Tastatursteuerung). Danach landest du in einer interaktiven Benutzeroberfläche direkt im Terminal. Du kannst dem Agenten nun Aufgaben in ganz normaler deutscher oder englischer Sprache stellen:

💬 "Erstelle eine neue Rust-Datei unter src/helper.rs und schreibe eine Funktion, die Fließkommazahlen rundet."

Der Agent wird daraufhin selbstständig die Datei anlegen und den Code hineinschreiben.

4. Die Fernsteuerung: Slash-Befehle

Slash-Befehle sind wie Kurzwahltasten. Wenn du im Eingabefeld ein / tippst, öffnet sich ein Menü mit nützlichen Steuerungsbefehlen für dich:

BefehlWas er macht
/settings (oder /config)Öffnet die Einstellungen (Farben, Profile etc.).
/keybindingsÖffnet einen Editor für Tastatur-Shortcuts.
/permissionsZeigt an, welche Rechte der Agent gerade hat (z. B. Schreibrechte).
/skillsListet alle geladenen Fähigkeiten (Custom Skills) auf.
/clearLöscht den aktuellen Chat-Verlauf und setzt das Gedächtnis des Agenten zurück.
/exitBeendet das Programm.

5. Wo werden Einstellungen und Protokolle gespeichert? (Pfade)

Das CLI legt alle wichtigen Konfigurationen und Logdaten an einem zentralen Ort in deinem Benutzerverzeichnis ab: ~/.gemini/antigravity-cli/ (unter Windows C:\Users\DeinName\.gemini\antigravity-cli\).

Dort findest du:

  1. settings.json: Deine persönlichen Einstellungen (z. B. Farbthema).
  2. brain/<sitzungs-id>/: Die Protokolle (Transkripte) deiner Chats. Sehr nützlich, um später nachzulesen, was der Agent getan hat.
  3. plugins/: Ordner für Erweiterungen und Anbindungen an andere Tools (MCP-Server).

6. Leitplanken setzen: AGENTS.md & SKILLS.md

Damit der Agent nicht unkontrolliert Dateien in deinem Projekt ändert, kannst du ihm über zwei einfache Textdateien in deinem Projektordner feste Regeln und Fähigkeiten vorgeben.

6.1 AGENTS.md – Die Hausordnung für dein Projekt

Diese Datei legst du direkt im Hauptverzeichnis deines Projekts ab. Der Agent liest sie bei jedem Start automatisch.

  • Zweck: Du sagst dem Agenten, wie er Code formatieren soll, wo er schreiben darf und welche Verzeichnisbereiche für ihn tabu sind.
  • Vorteil: Er hält sich automatisch an deine Programmierstandards.

6.2 SKILLS.md – Die Arbeitsanweisungen (Playbooks)

Hier definierst du feste Arbeitsabläufe (sogenannte Skills), die der Agent auf Knopfdruck ausführen kann.

  • Beispiel: Ein Skill namens @run-tests, der erst das Projekt kompiliert und dann die Tests startet.
  • Tipp: Eigene Skills werden im Projektordner unter .agents/skills/ abgelegt und können im Prompt mit @name aufgerufen werden.

7. Subagenten: Arbeit im Team delegieren

Manche Aufgaben sind zu groß oder riskant für einen einzelnen Agenten. Deshalb kann der Hauptagent im Hintergrund Subagenten (Unter-Agenten) starten und ihnen Teilaufgaben übertragen.

7.1 Die 3 Workspace-Modi (Wo arbeitet der Subagent?)

Damit ein Subagent nicht versehentlich deinen Code überschreibt, während er etwas testet, gibt es drei Modi für seine Arbeitsumgebung:

  1. inherit (Vererben/Teilen):
    • Wie es funktioniert: Der Subagent arbeitet im selben Ordner wie du und der Hauptagent.
    • Ideal für: Schnelle Suchen oder kleine Dateiänderungen.
  2. branch (Kopie erstellen):
    • Wie es funktioniert: Es wird eine komplette, isolierte Kopie deines Projektordners erstellt.
    • Ideal für: Riskante Experimente. Der Subagent kann dort Code ändern und kompilieren, ohne dass deine Arbeitsdateien verändert werden.
  3. share (Geteiltes Arbeiten):
    • Wie es funktioniert: Ähnlich wie ein git worktree. Der Subagent arbeitet auf einem anderen Zweig (Branch) deines Git-Projekts im selben Speicherplatz.
    • Ideal für: Paralleles Arbeiten an verschiedenen Features ohne Datenmüll oder lange Kopierzeiten.

7.2 Regeln für Subagenten in AGENTS.md definieren

Du kannst in deiner AGENTS.md festlegen, was Subagenten dürfen. Hier ist ein konkretes Beispiel:

## Regeln für Subagenten (Subagent Policies)
- Alle Subagenten müssen standardmäßig im sicheren Modus 'branch' gestartet werden.
- Subagenten vom Typ 'Linter' dürfen Dateien nur LESEN, nicht schreiben.
- Subagenten vom Typ 'Refactoring' dürfen nur im Ordner '/src/helpers' schreiben.
- Die Ausführung von externen Netzwerkbefehlen (z. B. wget) ist für Subagenten deaktiviert.

8. Praktisches Beispiel: Subagenten steuern

A) Automatisches Playbook in SKILLS.md

Du kannst in deiner SKILLS.md einen Arbeitsablauf beschreiben, den der Agent Schritt für Schritt ausführen soll:

# Skill: @code-review

Führe eine automatisierte Code-Review durch:
1. Starte einen Subagenten vom Typ "Review-Experte" im Modus `branch`.
2. Lasse den Subagenten alle Dateien im Ordner `src/` auf Fehler prüfen.
3. Lass ihn ein Protokoll erstellen.
4. Schließe den Subagenten und zeige das Ergebnis im Hauptchat an.

B) Steuerung per Python-Code

Wenn du eigene Skripte schreiben willst, kannst du das offizielle Python-SDK (google-antigravity) nutzen:

import asyncio
from google.antigravity import Agent, LocalAgentConfig

async def main():
    # 1. Konfiguration für den Haupt-Agenten erstellen
    config = LocalAgentConfig(
        system_instructions=(
            "Du bist der Chef-Agent. Wenn Aufgaben zu kompliziert werden, "
            "delegiere sie an spezialisierte Subagenten."
        ),
        tools=[]  # Hier könnten eigene Werkzeuge stehen
    )

    # 2. Den Agenten starten
    async with Agent(config) as main_agent:
        # 3. Dem Agenten eine Aufgabe geben
        # Der Agent entscheidet selbstständig, wann er Subagenten startet!
        response = await main_agent.chat(
            "Analysiere die Rust-Dateien in src/ und verbessere den Code."
        )
        
        # 4. Antwort ausgeben
        print("Antwort des Agenten:")
        print(await response.text())

if __name__ == "__main__":
    asyncio.run(main())

💡 Zusammenfassung für die Hosentasche

  • Befehl: Mit agy startest du das CLI im Projektordner.
  • Regeln: In AGENTS.md legst du fest, was die Agenten tun dürfen.
  • Fähigkeiten: In SKILLS.md hinterlegst du Arbeitsabläufe (z. B. @review).
  • Delegieren: Subagenten teilen sich die Arbeit und nutzen wahlweise den Modus inherit, branch oder share.
  • Sicherheit: Alles läuft sicher verpackt in einer Sandbox.
