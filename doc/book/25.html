Kapitel 25: Der Slice-Typ (Slices)

Slices sind eines der mächtigsten Werkzeuge in Rust, um sicher und ohne zusätzliche Allokationen auf Teilausschnitte von Kollektionen zuzugreifen. Sie ermöglichen es Ihnen, Speicherbereiche effizient zu referenzieren, ohne deren Besitzer zu sein.

1. Lernziele & Lernplan

Lernziele

  • Sie können Funktionen entwerfen, die Slices als Parameter akzeptieren, und den Nutzen von Deref Coercion erklären.
  • Sie können Array-Slices vom Typ &[T] anwenden und gängige Slice-Methoden fehlerfrei einsetzen.

2. Die Definition (Der präzise Einstieg)

Ein Slice (Ausschnitt) ist eine Referenz auf eine zusammenhängende Sequenz von Elementen in einer Collection, ohne diese Collection zu besitzen. Da ein Slice eine Referenz ist, unterliegt er den Ausleihregeln (Borrowing) von Rust. Er besitzt keinen eigenen Heap-Speicher, sondern verweist (als sogenannter Fat Pointer) direkt auf einen zusammenhängenden Speicherbereich einer bereits existierenden Kollektion.

3. Das Problem & Die Motivation (Die Ausgangslage)

Stellen Sie sich vor, Sie sollen eine Funktion schreiben, die einen String mit durch Leerzeichen getrennten Wörtern entgegennimmt und das erste gefundene Wort zurückgibt. Findet die Funktion kein Leerzeichen, soll der gesamte String zurückgegeben werden.

Ohne Slices müssten wir versuchen, die Position des Leerzeichens als Zahl (usize) zurückzugeben. Das Problem hierbei ist, dass diese Zahl separat vom String gespeichert wird. Wenn sich der ursprüngliche String ändert (z. B. gelöscht oder überschrieben wird), bleibt unsere Index-Variable bestehen. Der Index verliert seine Gültigkeit, ohne dass der Compiler dies bemerkt, was im weiteren Programmverlauf zu Fehlern oder Systemabstürzen führt.

4. Der naive Versuch (Der fehlerhafte Code)

Hier ist ein erster, naiver Entwurf, der versucht, die Endposition des ersten Wortes als Zahl zurückzugeben:

fn first_word(s: &String) -> usize {
    let bytes = s.as_bytes(); // Umwandlung in ein Byte-Array zur zeichenweisen Prüfung

    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return i; // Leerzeichen gefunden -> Index zurückgeben
        }
    }

    s.len() // Kein Leerzeichen gefunden -> Gesamtlänge zurückgeben
}

fn main() {
    let mut s = String::from("hello world");
    let word_end = first_word(&s); // word_end erhält den Wert 5

    s.clear(); // Der String wird geleert (""). Seine Länge ist nun 0!

    // word_end ist immer noch 5!
    // Wenn wir nun versuchen, auf die ersten 5 Zeichen von s zuzugreifen,
    // stürzt das Programm ab oder liefert ungültige Daten.
    println!("Das erste Wort endet bei Index: {}", word_end);
}

5. Die Anatomie des Fehlers (Fehleranalyse & Compiler-Feedback)

Was sagt das System?

Das obige Programm lässt sich problemlos kompilieren! Der Rust-Compiler sieht keinen Fehler, da word_end vom Typ usize ist. usize ist ein primitiver Typ, der das Copy-Trait implementiert und völlig unabhängig vom Zustand der Variable s ist.

Der Blick hinter die Kulissen (Speicherlayout)

  1. Vor dem Leeren (s.clear()):
    • Stack: s hält einen Pointer auf den Heap (z. B. 0x500), die Länge 11 und die Kapazität 11.
    • Heap: An Adresse 0x500 liegen die ASCII-Bytes für "hello world".
    • Stack: word_end enthält die Zahl 5.
  2. Nach dem Leeren (s.clear()):
    • Heap: Die Daten an Adresse 0x500 werden ungültig gemacht/gelöscht. Die Länge von s im Stack wird auf 0 gesetzt.
    • Stack: word_end ist unverändert 5.
  3. Die Fehlerquelle: Wenn wir nun versuchen, auf den Bereich &s[0..word_end] zuzugreifen, stellt Rust zur Laufzeit fest, dass die Länge von s nur 0 beträgt, der angeforderte Index 5 jedoch außerhalb liegt. Das Programm bricht sofort mit einer kontrollierten Panik ab (index out of bounds).

6. Die Lösung

Rust bietet mit String-Slices (&str) eine elegante Möglichkeit, Teilausschnitte typsicher zu referenzieren. Der Compiler garantiert, dass die Slices niemals länger existieren als die Daten, auf die sie verweisen.

Hier ist die korrekte Implementierung:

fn first_word(s: &str) -> &str {
    let bytes = s.as_bytes();

    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return &s[0..i]; // Gibt einen Ausschnitt bis zum Leerzeichen zurück
        }
    }

    &s[..] // Gibt den gesamten String als Slice zurück
}

fn main() {
    let mut s = String::from("hello world");
    
    let word = first_word(&s); // word ist ein Slice (&str), das auf s zeigt

    s.clear(); // FEHLER! Der Compiler blockiert diesen Aufruf.

    println!("Das erste Wort ist: {}", word);
}

Die Compiler-Fehlermeldung

Wenn wir versuchen, diesen Code zu kompilieren, erhalten wir folgendes Feedback vom Borrow Checker:

error[E0502]: cannot borrow `s` as mutable because it is also borrowed as immutable
  --> src/main.rs:16:5
   |
14 |     let word = first_word(&s);
   |                           -- immutable borrow occurs here
15 | 
16 |     s.clear(); // error!
   |     ^^^^^^^^^ mutable borrow occurs here
17 | 
18 |     println!("Das erste Wort ist: {}", word);
   |                                        ---- immutable borrow later used here

Da word eine aktive, unveränderbare Referenz (&str) auf einen Teil von s hält, verbietet Rust jede veränderbare Operation (wie s.clear()) auf dem gesamten String, solange diese Referenz noch verwendet wird. Die Speicherintegrität ist gerettet!

7. Kleines Tutorial (Schritt-für-Schritt-Praxis)

Wir erstellen nun Schritt für Schritt einen einfachen Log-Parser, der Zeilen im Format [LOG_LEVEL] Nachricht einliest und beide Bestandteile sicher als Slices zurückgibt.

EVA-Struktur des Parsers:

  • Eingabe (Input): Eine Log-Zeile als String-Slice (&str).
  • Verarbeitung (Processing): Suche nach den eckigen Klammern [ und ] sowie dem Leerzeichen zur Trennung.
  • Ausgabe (Output): Ein Tupel bestehend aus dem Log-Level-Slice und dem Nachrichten-Slice (&str, &str).

Schritt 1: Das Grundgerüst des Parsers definieren

Wir legen die Funktion fest, die nach den Begrenzungszeichen sucht:

#![allow(unused)]
fn main() {
fn parse_log_line(line: &str) -> Option<(&str, &str)> {
    // Schritt 2: Suchen der öffnenden und schließenden eckigen Klammern
    if !line.starts_with('[') {
        return None;
    }

    let end_bracket = line.find(']')?;
    
    // Schritt 3: Extrahieren des Log-Levels (ohne die Klammern)
    let log_level = &line[1..end_bracket];

    // Die Nachricht beginnt nach der schließenden Klammer und einem Leerzeichen
    let msg_start = end_bracket + 2;
    if msg_start >= line.len() {
        return None;
    }
    
    let message = &line[msg_start..];

    Some((log_level, message))
}
}

Schritt 4: Den Parser in der Praxis nutzen

fn main() {
    let log_entry = String::from("[ERROR] Verbindung zur Datenbank fehlgeschlagen");
    
    if let Some((level, msg)) = parse_log_line(&log_entry) {
        println!("Log-Level extrahiert: {}", level);
        println!("Nachricht extrahiert: {}", msg);
        
        // log_entry.clear(); // Würde einen Compilerfehler erzeugen, da level und msg noch leben!
    } else {
        println!("Ungültiges Log-Format!");
    }
}

8. Mentale Modelle & Deep Dive (Hintergrundwissen)

Das Speicherlayout eines Slices (Fat Pointer)

Ein normaler Referenz-Pointer auf ein Datenobjekt (z. B. &i32) belegt auf einem 64-Bit-System 8 Bytes, da er lediglich eine Speicheradresse speichert. Ein Slice hingegen ist ein Fat Pointer und belegt 16 Bytes im Stack:

  1. Pointer (8 Bytes): Zeigt auf das erste Element des Ausschnitts im Speicher.
  2. Länge (8 Bytes): Speichert die Anzahl der Elemente, die zum Slice gehören.
       String "hello world" im Heap
       +---+---+---+---+---+---+---+---+---+---+---+
Heap:  | h | e | l | l | o |   | w | o | r | l | d |
       +---+---+---+---+---+---+---+---+---+---+---+
         ^                   ^
         |                   |
       +---------+---------+ |
Stack: | Pointer | Länge:5 |-+ (Slice `world` zeigt ab Index 6 auf 5 Bytes)
       +---------+---------+

Vergleich: String vs &str und Vec<T> vs &[T]

  • Besitzer-Typen (String, Vec<T>): Haben die Hoheit über den Speicher. Sie liegen auf dem Stack mit 24 Bytes (Pointer auf Heap, Länge, Kapazität) und allozieren dynamischen Speicher auf dem Heap.
  • Slice-Typen (&str, &[T]): Haben keine Kapazität, da sie nicht wachsen können. Sie belegen auf dem Stack nur 16 Bytes (Pointer, Länge) und verweisen auf fremden Speicher (der auf dem Stack, Heap oder im statischen Programmcode liegen kann).

9. Drei praktische Übungen (Herausforderungen)

Übung 1 (Leicht - Syntax festigen)

Schreiben Sie eine Funktion last_word(s: &str) -> &str, die das letzte Wort in einem String zurückgibt. Wenn kein Leerzeichen vorhanden ist, soll der gesamte String zurückgegeben werden.

  • Lösungshinweis: Nutzen Sie die Methode .rfind(' '), um rückwärts nach dem ersten Leerzeichen zu suchen.

Übung 2 (Mittel - Logik erweitern)

Schreiben Sie eine Funktion trim_spaces(s: &str) -> &str, die führende und nachfolgende Leerzeichen aus einem String-Slice abschneidet und den bereinigten Teilausschnitt zurückgibt.

  • Lösungshinweis: Suchen Sie den ersten Index, der kein Leerzeichen ist, und den letzten Index von hinten. Nutzen Sie dafür eventuell Iteratoren oder Methoden wie .chars().

Übung 3 (Schwer - Transferleistung)

Implementieren Sie eine generische Funktion find_subslice<T: PartialEq>(data: &[T], pattern: &[T]) -> Option<usize>, die das erste Vorkommen eines Musterausschnitts (pattern) in einem größeren Array-Slice (data) sucht und den Startindex zurückgibt.

  • Lösungshinweis: Verwenden Sie die Methode .windows() auf dem Slice data, um Teilausschnitte der Länge von pattern nacheinander zu vergleichen.

10. Lernstrategie, Selbsteinschätzung & Merkzettel („Verstehen besser verstehen“)

Merkzettel (Cheat Sheet)

Range-Syntax im Überblick

SyntaxBedeutungBeispiel (für s = "hello")Ergebnis

&s[..2]Start weglassen (ab Anfang)&s[..2]"he"
&s[3..5]Von Index 3 bis vor Index 5&s[3..5]"lo"
&s[3..]Ende weglassen (bis Ende)&s[3..]"lo"
&s[..]Komplettes Slice&s[..]"hello"

Wichtige API-Methoden für str (String-Slices)

  • pub const fn len(&self) -> usize: Gibt die Länge des Slices in Bytes zurück.
    • Beispiel: "hallo".len() liefert 5.
  • pub const fn is_empty(&self) -> bool: Prüft, ob das Slice leer ist.
    • Beispiel: "".is_empty() liefert true.
  • pub const fn as_bytes(&self) -> &[u8]: Gibt eine Byte-Slice-Ansicht des Strings zurück.
  • pub fn chars(&self) -> Chars<'_>: Liefert einen Iterator über die Unicode-Zeichen (wichtig bei UTF-8).
  • pub fn contains<'a, P>(&'a self, pat: P) -> bool: Prüft, ob ein Muster enthalten ist.
    • Beispiel: "rust".contains("us") liefert true.
  • pub fn starts_with<'a, P>(&'a self, pat: P) -> bool: Prüft Präfixe.
  • pub fn ends_with<'a, P>(&'a self, pat: P) -> bool: Prüft Suffixe.
  • pub fn find<'a, P>(&'a self, pat: P) -> Option<usize>: Liefert den ersten Byte-Index des Musters.
  • pub fn trim(&self) -> &str: Entfernt führende und folgende Whitespaces als Slice.

Wichtige API-Methoden für [T] (Array-Slices)

  • pub const fn first(&self) -> Option<&T>: Gibt das erste Element als Referenz zurück.
  • pub const fn last(&self) -> Option<&T>: Gibt das letzte Element zurück.
  • pub fn get<I>(&self, index: I) -> Option<&I::Output>: Holt Element sicher (gibt bei Index-Fehlern None statt Panic).
  • pub fn binary_search(&self, x: &T) -> Result<usize, usize>: Führt Binärsuche auf sortiertem Slice durch.
  • pub fn sort(&mut self): Sortiert das Slice (benötigt veränderbare Ausleihe &mut [T]).
  • pub fn reverse(&mut self): Kehrt die Elementreihenfolge um.
  • pub fn chunks(&self, chunk_size: usize) -> Chunks<'_, T>: Teilt Slice in gleich große Stücke.
  • pub fn windows(&self, size: usize) -> Windows<'_, T>: Erzeugt ein gleitendes Fenster über die Elemente.

11. Zusammenfassung

  • Slices erlauben den sicheren Zugriff auf zusammenhängende Teilbereiche einer Kollektion ohne Eigentumsanspruch (Ownership).
  • Sie werden als Fat Pointer (Speicheradresse + Elementanzahl) auf dem Stack repräsentiert und sind stets unveränderliche oder veränderliche Referenzen (&str, &[T]).
  • Sie verhindern Out-of-Sync-Fehler (ungültige Indizes), da der Borrow Checker sicherstellt, dass die Kollektion nicht verändert oder gelöscht werden kann, solange ein Slice auf sie verweist.
  • Funktionen sollten bevorzugt Slices als Parameter akzeptieren (z. B. &str statt &String), da dies dank Deref Coercion sowohl Strings als auch Literale abdeckt.
