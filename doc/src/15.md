# Kapitel 15: Kontrollstrukturen – Bedingungen, Musterabgleich und Schleifen

Im echten Leben treffen wir ständig Entscheidungen: *„Wenn es regnet, nehme ich einen Regenschirm, andernfalls gehe ich ohne.“* Oder wir wiederholen eine Tätigkeit: *„Solange der Teller nicht leer ist, esse ich weiter.“*

In der Programmierung nennen wir diese Mechanismen **Kontrollstrukturen**. Sie steuern den Ablauf deines Programms und sorgen dafür, dass dein Code auf unterschiedliche Situationen reagieren kann.

In diesem Kapitel gehen wir ganz genau ins Detail und schauen uns an, wie Rust Entscheidungen und Wiederholungen handhabt. Rust hat hier einige Besonderheiten und Sicherheitsgarantien, die sich von anderen Sprachen unterscheiden.

---

## 1. Warum brauchen wir Kontrollstrukturen? (Einsatzgebiete)

Ohne Kontrollstrukturen würde ein Computerprogramm stur Zeile für Zeile von oben nach unten ausführen. Es gäbe keine Interaktivität. In der Praxis nutzen wir Kontrollstrukturen für folgende typische Aufgaben:

### Einsatzgebiete für Entscheidungen (`if` / `else` und `match`)
*   **Benutzereingaben prüfen**: Ist das eingegebene Passwort lang genug? Wenn ja, logge den Nutzer ein. Wenn nein, zeige eine Fehlermeldung (`if-else`).
*   **Sicherheitsprüfungen**: Hat der aktuelle Benutzer Admin-Rechte? Nur dann darf der sensible Lösch-Button gedrückt werden (`if`).
*   **Zustandsmaschinen (Status-Steuerung)**: In einem Spiel befindet sich die Spielfigur im Zustand `Laufen`, `Springen` oder `Fallen`. Je nach Zustand werden andere Animationen abgespielt (`match`).
*   **API-Antworten verarbeiten**: Ein Webserver antwortet mit verschiedenen Statuscodes (z. B. `200 OK`, `404 Not Found`, `500 Server Error`). Je nach Code reagiert das Programm anders (`match`).

### Einsatzgebiete für Schleifen (`loop`, `while` und `for`)
*   **Spiele-Schleifen (Game Loops)**: Jedes Computerspiel läuft in einer Endlosschleife. Sie liest die Tasten ein, berechnet die Physik und zeichnet das Bild auf den Monitor – und das 60-mal oder öfter pro Sekunde (`loop`).
*   **Dienste im Hintergrund (Server)**: Ein Webserver muss permanent im Hintergrund laufen und auf Anfragen warten. Er darf sich niemals von alleine beenden (`loop`).
*   **Dateien einlesen**: Wenn du eine große Textdatei Zeile für Zeile ausliest, nutzt du eine Schleife, die so lange läuft, wie noch Text in der Datei übrig ist (`while`).
*   **Datenverarbeitung (Listen & Tabellen)**: Du möchtest alle Preise in einem Warenkorb zusammenrechnen oder die Namen aller Schüler einer Klasse alphabetisch sortieren (`for`).

## 2. Ausdrücke (Expressions) vs. Anweisungen (Statements)

Um Rusts Kontrollstrukturen zu verstehen, müssen wir einen kurzen Blick auf den Unterschied zwischen **Ausdrücken** und **Anweisungen** werfen:

1.  **Anweisungen (Statements)**: Sie führen eine Aktion aus, geben aber keinen Wert zurück. Sie enden in Rust fast immer mit einem Semikolon `;`.
    *   *Beispiel*: `let x = 5;` (weist einen Wert zu, gibt aber selbst nichts zurück).
2.  **Ausdrücke (Expressions)**: Sie berechnen ein Ergebnis und geben einen Wert zurück. Sie haben **kein** Semikolon am Ende.
    *   *Beispiel*: `5 + 5` (wertet sich zu `10` aus).

In Rust sind fast alle Kontrollstrukturen (wie `if` oder `loop`) Ausdrücke. Das bedeutet, sie liefern uns einen Wert zurück, den wir direkt verwenden können.

## 3. Entscheidungen mit `if` und `else`

Eine Bedingung prüft, ob eine Aussage wahr (`true`) oder falsch (`false`) ist.

### 3.1 Die Grundsyntax
```rust
fn main() {
    let alter = 18;

    if alter >= 18 {
        println!("Du bist volljährig!");
    } else {
        println!("Du bist noch minderjährig.");
    }
}
```

*   **Keine Klammern**: Du brauchst in Rust keine runden Klammern `()` um die Bedingung zu schreiben (also `if alter >= 18` statt `if (alter >= 18)`).
*   **Strikte Typen**: Die Bedingung **muss** ein echter Wahrheitswert (`bool`) sein. Rust konvertiert Zahlen oder Texte nicht automatisch in Wahrheitswerte (es gibt kein „truthy“ oder „falsy“).

### 3.2 `if` als Ausdruck verwenden
Da `if` ein Ausdruck ist, kannst du das Ergebnis direkt einer Variablen zuweisen:

```rust
fn main() {
    let bedingung = true;

    // Weist 'nummer' den Wert 5 oder 6 zu
    let nummer = if bedingung { 5 } else { 6 };

    println!("Der Wert ist: {}", nummer); // Gibt 5 aus
}
```

> [!IMPORTANT]
> Wenn du `if` als Ausdruck nutzt, müssen der `if`- und der `else`-Zweig **den gleichen Datentyp** zurückgeben! Ein Code wie `let x = if bedingung { 5 } else { "Fehler" };` führt zu einem Kompilierfehler.

## 4. Musterabgleich mit `match` (Die Superkraft von Rust)

Wenn du viele verschiedene Fälle prüfen musst, werden `if-else`-Ketten schnell unübersichtlich. Rust bietet dafür eine der mächtigsten Kontrollstrukturen überhaupt: **`match`** (Musterabgleich). 

Man kann sich `match` wie eine hochentwickelte Version des `switch`-Befehls aus anderen Sprachen vorstellen.

### 4.1 Grundlegender Aufbau von `match`
```rust
fn main() {
    let rolle = "Admin";

    match rolle {
        "Admin" => println!("Vollzugriff auf alle Systeme."),
        "Moderator" => println!("Beiträge bearbeiten und löschen."),
        "Nutzer" => println!("Beiträge lesen und schreiben."),
        _ => println!("Keine Rechte vorhanden."), // Der Auffang-Fall (Default)
    }
}
```

*   **Der Zweig-Aufbau**: Jeder Fall (Zweig) besteht aus einem Muster (z. B. `"Admin"`), gefolgt von dem Pfeil `=>` und der auszuführenden Aktion. Die einzelnen Zweige werden durch Kommas getrennt.
*   **Der Platzhalter `_`**: Dies ist der „Auffang-Fall“ (ähnlich wie `default` in anderen Sprachen). Er fängt alle Werte ab, die nicht explizit darüber aufgelistet sind.

### 4.2 Die wichtigste Regel: Vollständigkeit (Exhaustiveness)
Der Rust-Compiler zwingt dich dazu, **jeden einzelnen möglichen Fall** abzudecken! Wenn du einen vergisst, kompiliert dein Programm nicht.

Ein Beispiel mit Zahlen:
```rust
fn main() {
    let wuerfel = 3;

    match wuerfel {
        1 => println!("Eins gewürfelt!"),
        2 => println!("Zwei gewürfelt!"),
        3 => println!("Drei gewürfelt!"),
        // Hier würde der Compiler meckern, weil 4, 5, 6 etc. fehlen.
        _ => println!("Andere Zahl gewürfelt!"), // Löst das Problem
    }
}
```

## 5. Schleifen – Code wiederholen

Schleifen wiederholen Code. Rust bietet drei Arten: `loop`, `while` und `for`.

### 5.1 `loop` und Schleifen-Labels (Loop Labels)
`loop` läuft unendlich lange weiter, bis wir `break` aufrufen. 

Eine Besonderheit in Rust ist, dass wir Schleifen benennen können (**Labels**). Das ist extrem nützlich, wenn du Schleifen ineinander verschachtelst und die *äußere* Schleife aus der *inneren* Schleife heraus abbrechen willst:

```rust
fn main() {
    let mut x = 0;

    // Wir geben der äußeren Schleife den Namen 'aeusserer_kreis
    'aeusserer_kreis: loop {
        println!("Äußere Schleife startet");
        let mut y = 0;

        loop {
            println!("   Innere Schleife: x={}, y={}", x, y);
            if y == 2 {
                break; // Beendet nur die innere Schleife
            }
            if x == 2 {
                break 'aeusserer_kreis; // Beendet die äußere Schleife!
            }
            y += 1;
        }
        x += 1;
    }
    println!("Beide Schleifen beendet!");
}
```

*Hinweis*: Schleifen-Labels beginnen immer mit einem einfachen Anführungszeichen (z. B. `'name:`).

### 5.2 `while` – Schleife mit Bedingung
Eine `while`-Schleife läuft so lange, wie eine Bedingung wahr (`true`) ist.

```rust
fn main() {
    let mut countdown = 3;

    while countdown > 0 {
        println!("{}...", countdown);
        countdown -= 1;
    }
    println!("Start!");
}
```

### 5.3 `for` – Iterieren über Sammlungen (Ranges & Iteratoren)
Die `for`-Schleife ist die sicherste und am häufigsten genutzte Schleife in Rust.

#### A) Über Bereiche laufen (Ranges)
*   `1..4` läuft von 1 bis 3 (die 4 ist exklusive).
*   `1..=4` läuft von 1 bis 4 (die 4 ist inklusive).

```rust
fn main() {
    // Gibt 1, 2, 3 aus
    for i in 1..4 {
        println!("i: {}", i);
    }
}
```

#### B) Über ein Array laufen mit `.iter()`
Um sicherzustellen, dass wir nicht außerhalb des Arrays zugreifen (Indexfehler), benutzen wir `for` in Kombination mit `.iter()`:

```rust
fn main() {
    let zahlen = [10, 20, 30];

    for zahl in zahlen.iter() {
        println!("Wert: {}", zahl);
    }
}
```

## 💡 Zusammenfassung für die Hosentasche

| Kontrollstruktur | Wann benutzen? | Besonderheit in Rust |
| :--- | :--- | :--- |
| **`if` / `else`** | Einfache Ja/Nein-Entscheidungen | Ist ein Ausdruck und kann Werte zurückgeben. |
| **`match`** | Komplexe Entscheidungen mit vielen Mustern | Compiler prüft zwingend auf Vollständigkeit (Exhaustiveness). |
| **`loop`** | Endlosschleifen oder Rückgabewerte bei Abbruch | Kann mit Labels (`'label:`) gezielt gesteuert werden. |
| **`while`** | Wiederholen, solange Bedingung gilt | Prüft Bedingung vor jedem Durchlauf. |
| **`for`** | Durchlaufen von Zahlenbereichen oder Arrays | Sicherste Option, da keine Bereichsüberschreitungen möglich sind. |
