# Kapitel 14: Antigravity CLI – Einstieg & Praxis

Das Antigravity CLI (aufrufbar über den Befehl `agy`) ist das offizielle Terminal-Interface für Googles agentenbasierte Entwicklungsplattform. Es ermöglicht dir, KI-Agenten direkt aus deiner Konsole heraus zu steuern, komplexe mehrstufige Änderungen (Multi-File-Edits) durchzuführen und deine Entwicklungsumgebung tastaturgesteuert zu verwalten.

---

## 1. Installation

Die Installation erfolgt über ein kurzes Terminal-Skript, welches das ausführbare Programm lädt:

*   **Linux / macOS**:
    ```bash
    curl -fsSL https://antigravity.google/cli/install.sh | bash
    ```
    Das Skript installiert die Binärdatei unter `~/.local/bin/agy`.
*   **Windows (PowerShell)**:
    ```powershell
    irm https://antigravity.google/cli/install.ps1 | iex
    ```

---

## 2. Erste Schritte mit `agy`

Um das CLI zu starten, navigierst du im Terminal in dein Projektverzeichnis und rufst `agy` auf:

```bash
cd /dein/projektpfad
agy
```

Beim ersten Start öffnet sich ein kurzer Einrichtungsassistent für Farbthemen und Darstellungsmodi. Danach befindest du dich im interaktiven Prompt. Hier kannst du Aufgaben in natürlicher Sprache eingeben, wie z. B.:
> *"Erstelle eine neue Rust-Datei unter src/helper.rs und implementiere eine Funktion zum Runden von Fließkommazahlen."*

---

## 3. Die wichtigsten Slash-Befehle (Agentensteuerung)

Über Slash-Befehle kannst du das Verhalten des Agenten und des CLI während der Sitzung steuern. Gib dazu einfach `/` in der Eingabezeile ein:

*   **`/settings`** (oder `/config`): Öffnet ein interaktives Einstellungsmenü im Terminal.
*   **`/keybindings`**: Öffnet einen Editor für Tastatur-Shortcuts.
*   **`/permissions`**: Zeigt die aktiven Tool- und Dateizugriffsrechte an.
*   **`/skills`**: Zeigt eine Liste aller geladenen Custom Skills an.
*   **`/clear`**: Setzt den aktuellen Kontext und den Chatverlauf zurück.
*   **`/exit`**: Beendet die interaktive TUI-Sitzung.

---

## 4. Konfigurationsdateien & Pfade

Das CLI speichert alle Konfigurationen und Logs in deinem Benutzerverzeichnis unter `~/.gemini/antigravity-cli/`:

1.  **`settings.json`**: Enthält deine persistenten Einstellungen.
2.  **`brain/<conversation-id>/`**: Hier werden alle deine Sitzungen, Transkripte und Logdateien gespeichert.
3.  **`plugins/`**: Ort für Erweiterungen und MCP-Serverkonfigurationen.

## 5. Projektkonfiguration: `AGENTS.md` & `SKILLS.md`

Für eine detaillierte Steuerung der Agenten in deinem Projekt nutzt das CLI zwei wichtige lokale Dateien im Projektverzeichnis:

### `AGENTS.md` (Projektregeln & Kontext)
Diese Datei enthält projektspezifische Richtlinien, Verzeichniszuweisungen und Designausschlüsse. Der Agent liest diese Datei bei jedem Start automatisch ein. Dadurch weiß er beispielsweise, wo Code hingeschrieben werden darf, und hält sich an deine Programmierstandards.

### `SKILLS.md` (Custom Skills & Playbooks)
Skills sind vordefinierte Arbeitsabläufe oder Playbooks, die dem Agenten beibringen, wie er komplexe, wiederkehrende Aufgaben erledigen soll (z. B. *"Kompiliere das Projekt und führe Tests aus"*).
- Du kannst diese Skills direkt im Prompt mit dem Präfix `@` aufrufen (z. B. `@run-tests`).
- Lokale Skills werden im Projektordner unter `.agents/skills/` abgelegt.

### Subagenten & Workspace-Verzeichnisse (Delegation)
Wenn eine Aufgabe zu komplex für einen einzelnen Agenten ist, kann das CLI im Hintergrund **Subagenten** erstellen und aufrufen. Diese führen spezifische Teilaufgaben (z. B. Code-Recherche oder Fehlerbehebung) in eigenen Workspace-Verzeichnissen aus. Es gibt drei Modi, wie das Verzeichnis für einen Subagenten konfiguriert werden kann:

1.  **`inherit` (Standard)**: Der Subagent arbeitet direkt im selben Verzeichnis wie der Hauptagent.
2.  **`branch`**: Es wird eine komplette, isolierte Kopie des Projektverzeichnisses erstellt. So kann der Subagent ungestört experimentieren, ohne deinen aktuellen Code zu überschreiben.
3.  **`share`**: Erstellt ein geteiltes Verzeichnis (ähnlich wie ein `git worktree`). Dies erlaubt unabhängiges Arbeiten auf verschiedenen Branches, spart aber Speicherplatz, da die Dateien nicht dupliziert werden.

## 6. Eigene Regeln für Subagenten definieren (`AGENTS.md`)

Du kannst das Verhalten, die Rechte und die Rollen von Subagenten durch spezielle Abschnitte in deiner lokalen `AGENTS.md` präzise steuern:

*   **Einschränkung der Dateirechte**: Du kannst festlegen, welche Subagenten Schreibrechte erhalten. Beispielsweise darf ein Subagent für Code-Review (`readonly`) nur Dateien analysieren, während ein Refactoring-Subagent (`readwrite`) im Verzeichnis `/src` schreiben darf.
*   **Festlegen von Tool-Verboten**: Du kannst verbieten, dass Subagenten bestimmte Befehle ausführen (z. B. externe Netzwerkanfragen via `curl` oder System-Updates).
*   **Vorgabe des Workspace-Modus**: Du kannst erzwingen, dass Subagenten für kritische Code-Änderungen immer im `branch`-Modus gestartet werden, um die Stabilität des Haupt-Branches zu sichern.

### Beispiel für Subagenten-Regeln in `AGENTS.md`:
```markdown
## Subagenten-Regeln (Subagent Policies)
- Alle Subagenten müssen standardmäßig im Modus 'branch' gestartet werden.
- Subagenten des Typs 'Linter' haben ausschließlich Lesezugriff auf das Projekt.
- Subagenten des Typs 'Refactoring' dürfen nur im Verzeichnis '/src/helpers' schreiben.
- Die Ausführung von externen Netzwerkbefehlen (z. B. wget) ist für Subagenten deaktiviert.
```

## 7. Beispiel-Code: Subagenten in der Praxis

Es gibt zwei Wege, wie Subagenten gesteuert und deklariert werden:

### A) Deklaration in `SKILLS.md` (TUI / Playbooks)
In deiner `SKILLS.md` kannst du dem Hauptagenten ein Playbook vorgeben, wie er einen Subagenten für eine bestimmte Aufgabe starten und anweisen soll:

```markdown
# Skill: @code-review

Führe eine automatisierte Code-Review mit einem spezialisierten Subagenten durch:
1. Starte einen Subagenten vom Typ "Review-Experte" im Modus `branch` (isolierte Kopie).
2. Weise den Subagenten an, alle Dateien im Ordner `src/` auf Sicherheitslücken zu prüfen.
3. Lass den Subagenten ein Feedback-Protokoll erstellen.
4. Schließe den Subagenten und präsentiere das Ergebnis im Hauptchat.
```

### B) Programmatisch mit dem Python SDK (`google-antigravity`)
Wenn du eigene Workflows programmierst, kannst du die Agenten und deren Orchestrierung direkt in Python steuern:

```python
import asyncio
from google.antigravity import Agent, LocalAgentConfig

async def main():
    # Konfiguration des Haupt-Agenten (Orchestrator)
    config = LocalAgentConfig(
        system_instructions=(
            "Du bist ein Orchestrator-Agent. Delegiere komplexe Aufgaben "
            "wie Refactoring oder Fehlersuche an spezialisierte Subagenten."
        ),
        tools=[]  # Eigene Tools und Hooks definieren
    )

    # Agent starten
    async with Agent(config) as main_agent:
        # Task absenden – der Agent entscheidet selbstständig,
        # wann er einen Subagenten (START_SUBAGENT) hinzuzieht
        response = await main_agent.chat(
            "Analysiere die Rust-Dateien in src/ und führe ein Refactoring durch."
        )
        print("Antwort des Agenten:")
        print(await response.text())

if __name__ == "__main__":
    asyncio.run(main())
```

## 💡 Merkzettel: Antigravity CLI

*   **Starten**: Im Projektordner mit `agy` aufrufen.
*   **Projekt-Regeln**: Über [AGENTS.md](file:///home/thorsten/RustKurs/AGENTS.md) im Projektverzeichnis anpassen (einschließlich Rollen und Berechtigungen für Subagenten).
*   **Custom Skills**: Playbooks in `SKILLS.md` definieren und mit `@skill-name` im Prompt starten.
*   **Subagenten-Verzeichnisse**: Drei Modi für Arbeitsbereiche: `inherit` (gleicher Ordner), `branch` (isolierte Kopie) oder `share` (geteiltes Verzeichnis).
*   **Sicherheit**: Lokale Shellbefehle laufen in einer abgesicherten **Terminal Sandbox** (z. B. `nsjail` unter Linux).
