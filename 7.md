## 2. Die Definition – Was ist ein Übungsprojekt?

### 2.1 Was ist ein Übungsprojekt?

Ein **Übungsprojekt** ist ein kleines, vollständiges Softwareprogramm, das gezielt dazu dient, theoretisch erlernte Konzepte in der Praxis anzuwenden und zu festigen. Im Gegensatz zu isolierten Code-Snippets, die einzelne Funktionen demonstrieren, integriert ein Übungsprojekt mehrere Konzepte gleichzeitig und erzeugt ein sinnvolles, benutzbares Ergebnis.

#### Merkmale eines guten Übungsprojekts

| Merkmal | Erläuterung |
|---|---|
| **Vollständigkeit** | Das Programm ist lauffähig und produziert ein sinnvolles Ergebnis |
| **Überschaubarkeit** | Der Code ist kurz genug, um ihn vollständig zu verstehen |
| **Lehrreichkeit** | Es werden mehrere Kernkonzepte gleichzeitig angewendet |
| **Erweiterbarkeit** | Das Projekt kann als Basis für komplexere Programme dienen |
| **Alltagsnähe** | Das Programm löst eine verständliche, realistische Aufgabe |

### 2.2 Das EVA-Prinzip

Das **EVA-Prinzip** ist ein fundamentales Konzept der Informatik, das den grundlegenden Aufbau jedes Computerprogramms beschreibt:

```
┌─────────────────────────────────────────────────────────┐
│                    EVA-PRINZIP                          │
│                                                         │
│   ┌─────────┐    ┌────────────────┐    ┌─────────┐     │
│   │         │    │                │    │         │     │
│   │ EINGABE │───>│  VERARBEITUNG  │───>│ AUSGABE │     │
│   │   (E)   │    │      (V)       │    │   (A)   │     │
│   │         │    │                │    │         │     │
│   └─────────┘    └────────────────┘    └─────────┘     │
│                                                         │
│   Tastatur       CPU / Logik           Bildschirm       │
│   Datei          Berechnungen          Datei            │
│   Netzwerk       Transformationen      Netzwerk         │
│   Sensoren       Entscheidungen        Drucker          │
└─────────────────────────────────────────────────────────┘
```

#### 2.2.1 Eingabe (E)

Die **Eingabe** bezeichnet alle Daten, die ein Programm von außen entgegennimmt. In Rust umfasst dies:

- Benutzereingaben über die Tastatur (`std::io::stdin`)
- Kommandozeilenargumente (`std::env::args`)
- Dateiinhalte (`std::fs::read_to_string`)
- Netzwerkdaten (`std::net::TcpStream`)
- Umgebungsvariablen (`std::env::var`)

In diesem Kapitel konzentrieren wir uns auf die **interaktive Tastatureingabe**.

#### 2.2.2 Verarbeitung (V)

Die **Verarbeitung** ist das Herzstück jedes Programms. Hier werden aus den Eingabedaten neue Ergebnisse berechnet. Typische Verarbeitungsschritte sind:

- Typkonvertierungen (String → Zahl)
- Arithmetische Berechnungen
- Vergleiche und Entscheidungen
- Schleifen und Iterationen
- Fehlerbehandlung

In Rust ist die Verarbeitung oft expliziter als in anderen Sprachen, weil Rust Sie zwingt, Fehlerfälle zu berücksichtigen.

#### 2.2.3 Ausgabe (A)

Die **Ausgabe** ist das Ergebnis der Verarbeitung, das dem Benutzer oder einem anderen System mitgeteilt wird. In Rust:

- `println!()` → Standardausgabe (stdout)
- `eprintln!()` → Fehlerausgabe (stderr)
- `print!()` → Standardausgabe ohne Zeilenumbruch
- `eprint!()` → Fehlerausgabe ohne Zeilenumbruch
- Dateiausgabe über `std::fs::write`

### 2.3 Das EVA-Prinzip in der Rust-Terminologie

```
EINGABE                    VERARBEITUNG               AUSGABE
─────────────────────      ──────────────────────     ──────────────────
std::io::stdin()           String → Zahl              println!("{}", x)
  .read_line(&mut buf)       .trim()                  eprintln!("{}", e)
  .expect("Fehler")          .parse::<i32>()          print!("Eingabe: ")
                             match result { ... }
                             Berechnungslogik
```

> [!NOTE]
> Das EVA-Prinzip wurde in den 1960er Jahren als didaktisches Modell entwickelt und ist heute noch der Ausgangspunkt für das Verstehen von Programmen aller Komplexitätsstufen – von einfachen Skripten bis hin zu verteilten Cloud-Systemen.

## 3. Das Problem & Die Motivation

### 3.1 Warum Theorie allein nicht ausreicht

Stellen Sie sich vor, Sie haben die Kapitel über Variablen, Typen und Kontrollstrukturen gelesen und verstanden. Sie können erklären, was ein `i32` ist, Sie wissen, dass `loop` eine Endlosschleife erzeugt, und Sie haben die Syntax von `if`/`else` verinnerlicht. Aber dann öffnen Sie einen leeren Editor und sollen ein einfaches interaktives Programm schreiben – und plötzlich wissen Sie nicht, wo Sie anfangen sollen.

Dieses Phänomen ist in der Informatikpädagogik gut bekannt. Es gibt einen fundamentalen Unterschied zwischen:

1. **Deklarativem Wissen**: Sie können erklären, *was* etwas ist
2. **Prozeduralem Wissen**: Sie können zeigen, *wie* man es anwendet

Übungsprojekte schließen diese Lücke. Sie zwingen Sie, beide Wissensarten zu kombinieren und dabei die kreative Leistung zu erbringen, die echte Softwareentwicklung ausmacht: einen Bedarf zu identifizieren und ihn durch strukturierten Code zu lösen.

### 3.2 Die Brücke zwischen Theorie und Praxis

| Theoretisches Konzept | Praxisanwendung im Übungsprojekt |
|---|---|
| Variablen und `mut` | `let mut eingabe = String::new()` – veränderliche Eingabepuffer |
| `i32`, `u32` Typen | Zufallszahl und Benutzereingabe als Zahlen verarbeiten |
| `loop` Schleife | Spielschleife, die so lange läuft, bis der Spieler gewinnt |
| `if`/`else` | Entscheidung: zu hoch, zu niedrig, oder korrekt? |
| `match` | Elegante Fallunterscheidung für `Ordering` und `Result` |
| `use`-Anweisungen | Externe Crate (`rand`) und Standardbibliothek importieren |
| Fehlerwerte | `Result<T, E>` bei `parse()` und `read_line()` verarbeiten |

### 3.3 Das Zahlenratespiel als ideales Lernprojekt

Das **Zahlenratespiel** ist aus mehreren Gründen das ideale erste Übungsprojekt:

**Vertrautheit**: Fast jeder kennt das Spiel aus der Kindheit. Es braucht keine Erklärung, wie es funktioniert. Das reduziert die kognitive Last auf das Wesentliche: den Code.

**Vollständigkeit**: Das Spiel hat einen klaren Anfang (Zufallszahl generieren), einen Mittelteil (Rateversuche mit Feedback) und ein Ende (Gewinn). Es ist ein vollständiges Programm, kein Fragment.

**Fehlerfälle**: Die Benutzereingabe ist inhärent unsicher. Der Benutzer könnte Buchstaben statt Zahlen eingeben. Das erzwingt echte Fehlerbehandlung.

**Erweiterbarkeit**: Das Spiel kann leicht erweitert werden: maximale Versuche, verschiedene Schwierigkeitsstufen, Highscore-Speicherung.

> [!IMPORTANT]
> Das Zahlenratespiel ist so bekannt, dass es auch im offiziellen Rust-Buch "The Rust Programming Language" als erstes Lernprojekt vorgestellt wird. Sie befinden sich damit in sehr guter Gesellschaft.

### 3.4 Was passiert ohne strukturiertes Vorgehen?

Ein typischer Anfänger ohne strukturiertes Vorgehen beginnt oft so:

```rust
// Anfänger-Versuch ohne Planung:
// "Ich schreibe einfach drauf los..."
fn main() {
    // Hmm, wie bekomme ich eine Zufallszahl?
    // Wie lese ich Eingaben?
    // Wie vergleiche ich die?
    // ...
}
```

Das Ergebnis: Frustration, leeres Blatt-Syndrom, aufgeben. Die Lösung ist strukturiertes Vorgehen durch **Pseudocode**.

## 4. Der naive Versuch – Häufige Anfängerfehler

Bevor wir die korrekte Lösung entwickeln, schauen wir uns an, wie ein typischer Anfänger – ohne vollständiges Verständnis der Fehlerbehandlung – dieses Problem angehen würde. Das Studium von Fehlern ist genauso lehrreich wie das Studium von korrektem Code.

### 4.1 Naiver Versuch: Ohne trim() und ohne Fehlerbehandlung

```rust
// FEHLERHAFTE VERSION – Nicht so schreiben!
use std::io;

fn main() {
    println!("Raten Sie eine Zahl zwischen 1 und 100!");

    let mut eingabe = String::new();

    io::stdin().read_line(&mut eingabe).unwrap();

    // FEHLER: trim() fehlt! Die Eingabe enthält noch '\n'
    let zahl: i32 = eingabe.parse().unwrap();
    //                              ^^^^^^^
    // PANIK wenn eingabe nicht parseable ist!
    // "1\n" kann nicht direkt zu i32 geparst werden!

    println!("Sie haben {} eingegeben.", zahl);
}
```

**Was hier falsch ist:**

1. **`trim()` fehlt**: Wenn der Benutzer `42` eingibt und Enter drückt, enthält `eingabe` den String `"42\n"` (unter Unix) oder `"42\r\n"` (unter Windows). Der Versuch, `"42\n"` direkt zu einem `i32` zu parsen, schlägt fehl.

2. **`.unwrap()` ohne Kontext**: `.unwrap()` verursacht eine **Panic** bei Fehler, anstatt eine sinnvolle Fehlermeldung zu geben. Für Produktionscode ist das inakzeptabel.

3. **Keine Wiederholungsschleife**: Das Programm liest genau eine Eingabe und endet dann. Kein echtes Spiel.

### 4.2 Naiver Versuch: Falsche Typannotation

```rust
// FEHLERHAFTE VERSION – Typfehler
use std::io;

fn main() {
    let mut eingabe = String::new();
    io::stdin().read_line(&mut eingabe).unwrap();
    eingabe = eingabe.trim(); // FEHLER!
    //                 ^^^^
    // trim() gibt &str zurück, nicht String!
    // Das passt nicht zum Typ von `eingabe`
}
```

Dieser Fehler ist besonders häufig. `trim()` gibt eine **Referenz** (`&str`) auf den getrimmten Teil des Strings zurück, keinen neuen `String`. Man kann den Rückgabewert nicht direkt einer `String`-Variablen zuweisen.

### 4.3 Naiver Versuch: Parse ohne Typinformation

```rust
// FEHLERHAFTE VERSION – Fehlende Typinformation
use std::io;

fn main() {
    let mut eingabe = String::new();
    io::stdin().read_line(&mut eingabe).unwrap();
    let zahl = eingabe.trim().parse(); // FEHLER!
    //                         ^^^^^
    // Rust weiß nicht, in welchen Typ geparst werden soll!
    // Compiler-Fehler: type annotations needed
}
```

Der Rust-Compiler benötigt Informationen, in welchen Typ konvertiert werden soll. Ohne Typannotation gibt er eine klare Fehlermeldung aus.

### 4.4 Naiver Versuch: Fehlende Abhängigkeit für rand

```rust
// FEHLERHAFTE VERSION – rand nicht in Cargo.toml
use rand::Rng; // FEHLER! rand ist kein Teil der Standardbibliothek

fn main() {
    let zufallszahl = rand::thread_rng().gen_range(1..=100);
    println!("{}", zufallszahl);
}
```

Ohne den Eintrag `rand = "0.8"` in `Cargo.toml` versteht der Compiler das Modul `rand` nicht.

> [!WARNING]
> Alle oben gezeigten Fehler sind **reale Fehler**, die Anfänger regelmäßig machen. Verstehen Sie diese Fehler jetzt gründlich – es wird Ihnen später viele Stunden des Debuggens ersparen.

## 5. Die Anatomie des Fehlers

Lassen Sie uns die Fehlermeldungen, die Rust bei den oben gezeigten fehlerhaften Programmen ausgibt, genau analysieren. Das Lesen von Compiler-Fehlermeldungen ist eine Kernkompetenz jedes Rust-Entwicklers.

### 5.1 Compiler-Fehler: Typkonflikt bei trim()

Wenn Sie versuchen, `eingabe = eingabe.trim();` zu schreiben:

```
error[E0308]: mismatched types
 --> src/main.rs:6:15
  |
6 |     eingabe = eingabe.trim();
  |               ^^^^^^^^^^^^^^ expected struct `String`, found `&str`
  |
  = note: expected struct `String`
             found reference `&str`
  = help: try using a conversion method: `eingabe.trim().to_string()`

For more information about this error, try `rustc --explain E0308`.
```

**Analyse**:
- `error[E0308]`: Typkonflikt
- `expected struct String, found &str`: Rust erwartet einen `String`, bekommt aber eine Referenz auf einen String-Slice (`&str`)
- `help: try using a conversion method: .to_string()`: Der Compiler gibt einen konkreten Lösungshinweis

### 5.2 Compiler-Fehler: Fehlende Typannotation bei parse()

```
error[E0284]: type annotations needed
 --> src/main.rs:7:35
  |
7 |     let zahl = eingabe.trim().parse();
  |                               ^^^^^ cannot infer type for type parameter `F` declared on the associated function `parse`
  |
help: consider specifying the type explicitly
  |
7 |     let zahl = eingabe.trim().parse::<F>();
  |                                    +++++

For more information about this error, try `rustc --explain E0284`.
```

**Analyse**:
- `error[E0284]`: Rust kann den Typ nicht inferieren
- `cannot infer type for type parameter F`: Die generische Funktion `parse()` weiß nicht, in welchen Typ sie konvertieren soll
- Lösung: Typparameter explizit angeben mit `.parse::<i32>()`

### 5.3 Laufzeitfehler: Panic bei unwrap()

Wenn der Benutzer `"abc"` eingibt und das Programm `.parse::<i32>().unwrap()` aufruft:

```
thread 'main' panicked at 'called `Result::unwrap()` on an `Err` value: 
ParseIntError { kind: InvalidDigit }', src/main.rs:8:42
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
```

**Analyse**:
- `thread 'main' panicked`: Das Programm hat abrupt abgebrochen
- `called Result::unwrap() on an Err value`: `.unwrap()` wurde auf einen Fehlerwert aufgerufen
- `ParseIntError { kind: InvalidDigit }`: Der konkrete Fehler – ein ungültiges Zeichen beim Parsen einer Ganzzahl

**Mit `RUST_BACKTRACE=1`** erhalten Sie zusätzlich den vollständigen Call-Stack, was bei komplexeren Programmen bei der Fehlersuche hilft:

```
$ RUST_BACKTRACE=1 cargo run
thread 'main' panicked at 'called `Result::unwrap()` on an `Err` value: 
ParseIntError { kind: InvalidDigit }', src/main.rs:8:42
stack backtrace:
   0: rust_begin_unwind
   1: core::panicking::panic_fmt
   2: core::result::unwrap_failed
   3: core::result::Result<T,E>::unwrap
   4: zahlenratespiel::main
```

### 5.4 Laufzeitfehler: Das trim()-Problem im Detail

Das folgende Experiment veranschaulicht das `trim()`-Problem sehr deutlich:

```rust
// Demo: Was enthält die Eingabe wirklich?
use std::io;

fn main() {
    let mut eingabe = String::new();
    io::stdin().read_line(&mut eingabe).unwrap();

    // Zeige die rohe Eingabe mit Debug-Ausgabe:
    println!("Rohe Eingabe (mit Debug): {:?}", eingabe);
    println!("Länge: {} Zeichen", eingabe.len());

    // Nach trim():
    let bereinigt = eingabe.trim();
    println!("Nach trim() (mit Debug): {:?}", bereinigt);
    println!("Länge nach trim(): {} Zeichen", bereinigt.len());
}
```

**Beispielausgabe** (Benutzer gibt `42` ein):

```
42
Rohe Eingabe (mit Debug): "42\n"
Länge: 3 Zeichen
Nach trim() (mit Debug): "42"
Länge nach trim(): 2 Zeichen
```

**Unter Windows** würde die Ausgabe sein:

```
42
Rohe Eingabe (mit Debug): "42\r\n"
Länge: 4 Zeichen
Nach trim() (mit Debug): "42"
Länge nach trim(): 2 Zeichen
```

> [!NOTE]
> Der `{:?}`-Format-Spezifizierer gibt den **Debug-Format** des Wertes aus. Für Strings bedeutet das: Die Anführungszeichen und Escape-Sequenzen (wie `\n` für Zeilenumbruch) werden sichtbar. Das ist extrem nützlich beim Debugging.

### 5.5 Der Unterschied zwischen expect() und unwrap()

Beide Methoden führen bei einem `Err`-Wert zu einer Panic, aber es gibt einen wichtigen Unterschied:

```rust
// Mit unwrap() – generische Fehlermeldung:
let zahl: i32 = eingabe.trim().parse().unwrap();
// → "called `Result::unwrap()` on an `Err` value: ParseIntError { ... }"

// Mit expect() – aussagekräftige Fehlermeldung:
let zahl: i32 = eingabe.trim().parse().expect("Bitte eine gültige Zahl eingeben!");
// → "Bitte eine gültige Zahl eingeben!: ParseIntError { ... }"
```

Verwenden Sie `.expect()` mit einer aussagekräftigen Nachricht, wenn Sie sicher sind, dass ein Fehler niemals auftreten sollte. Verwenden Sie `match` für Fehler, die zur Laufzeit durchaus auftreten können und graceful behandelt werden sollen.

## 6. Die Lösung – Vollständiges Zahlenratespiel

### 6.1 Pseudocode auf Deutsch

Bevor wir Code schreiben, formulieren wir den Algorithmus in Pseudocode. Das ist der Schlüssel zu strukturiertem Programmieren:

```
ALGORITHMUS: Zahlenratespiel

VORBEREITUNG:
  1. Generiere eine Zufallszahl zwischen 1 und 100 (inklusive)
  2. Setze Versuchszähler auf 0
  3. Gib Willkommensnachricht aus

SPIELSCHLEIFE (wiederhole bis Gewinn):
  4. Fordere Benutzer zur Eingabe auf
  5. Lese Benutzereingabe als Text

  VALIDIERUNG:
  6. Bereinige Eingabe (trim)
  7. Versuche, Text in Zahl zu konvertieren
  8. WENN Konvertierung fehlschlägt:
       Gib Fehlermeldung aus
       Gehe zu Schritt 4

  VERGLEICH:
  9. Erhöhe Versuchszähler um 1
  10. Vergleiche eingegebene Zahl mit Zufallszahl
      WENN eingabe < zufallszahl:
        Gib "Zu niedrig!" aus
      WENN eingabe > zufallszahl:
        Gib "Zu hoch!" aus
      WENN eingabe == zufallszahl:
        Gib Glückwunsch und Versuchsanzahl aus
        Beende Spielschleife

ABSCHLUSS:
  11. Programm endet
```

### 6.2 Abbildung Pseudocode → Rust-Syntax

| Pseudocode | Rust-Entsprechung |
|---|---|
| Zufallszahl generieren | `rand::thread_rng().gen_range(1..=100)` |
| Versuchszähler | `let mut versuche: u32 = 0;` |
| Willkommensnachricht | `println!("...")` |
| Spielschleife | `loop { ... }` |
| Eingabe lesen | `io::stdin().read_line(&mut eingabe)` |
| Eingabe bereinigen | `eingabe.trim()` |
| Text in Zahl konvertieren | `.parse::<u32>()` |
| Konvertierung fehlschlägt | `Err(_) => { continue; }` |
| Versuchszähler erhöhen | `versuche += 1;` |
| Vergleichen | `match eingabe_zahl.cmp(&geheimzahl)` |
| Zu niedrig | `Ordering::Less => println!("...")` |
| Zu hoch | `Ordering::Greater => println!("...")` |
| Gewonnen | `Ordering::Equal => { println!("..."); break; }` |

### 6.3 Projektstruktur mit Cargo

Erstellen Sie zunächst ein neues Cargo-Projekt:

```bash
cargo new zahlenratespiel
cd zahlenratespiel
```

Die entstandene Verzeichnisstruktur:

```
zahlenratespiel/
├── Cargo.toml        ← Projektmetadaten und Abhängigkeiten
└── src/
    └── main.rs       ← Ihr Hauptprogramm
```

### 6.4 Cargo.toml konfigurieren

Öffnen Sie `Cargo.toml` und fügen Sie die `rand`-Abhängigkeit hinzu:

```toml
[package]
name = "zahlenratespiel"
version = "0.1.0"
edition = "2021"

# Hier fügen wir externe Abhängigkeiten (Crates) hinzu:
[dependencies]
rand = "0.8"
```

**Erklärung der Felder:**

| Feld | Bedeutung |
|---|---|
| `[package]` | Metadaten über Ihr Projekt |
| `name` | Der Name des Programms/der Bibliothek |
| `version` | Versionsnummer im Semantic-Versioning-Format |

### 6.5 Vollständiger, lauffähiger Code

Hier ist das vollständige Zahlenratespiel. Lesen Sie den Code zunächst komplett durch, bevor Sie die Erklärungen lesen:

```rust
// Datei: src/main.rs
// Zahlenratespiel – Vollständige, lauffähige Version

use rand::Rng;               // Für Zufallszahlen-Funktionen
use std::cmp::Ordering;      // Für den Vergleich von Zahlen
use std::io;                 // Für Eingabe/Ausgabe

fn main() {
    // ─────────────────────────────────────────────────────
    // VORBEREITUNG
    // ─────────────────────────────────────────────────────

    println!("=== Willkommen beim Zahlenratespiel! ===");
    println!("Ich habe mir eine Zahl zwischen 1 und 100 gedacht.");
    println!("Können Sie sie erraten?");
    println!();

    // Zufallszahl generieren (1 bis 100, beide inklusive)
    let geheimzahl: u32 = rand::thread_rng().gen_range(1..=100);

    // Versuchszähler – muss veränderlich sein (mut)
    let mut versuche: u32 = 0;

    // ─────────────────────────────────────────────────────
    // SPIELSCHLEIFE
    // ─────────────────────────────────────────────────────

        println!("Bitte geben Sie Ihren Tipp ein:");

        // Eingabepuffer – muss leer sein vor jeder Benutzung
        let mut eingabe = String::new();

        io::stdin()
            .read_line(&mut eingabe)
            .expect("Fehler beim Lesen der Eingabe!");

        // Eingabe bereinigen und in Zahl umwandeln
        // trim() entfernt Whitespace (inkl. \n und \r\n)
        // parse::<u32>() konvertiert &str → u32
        let tipp: u32 = match eingabe.trim().parse::<u32>() {
            Ok(zahl) => zahl,   // Erfolgreich geparst
            Err(_) => {
                // Keine Zahl eingegeben – freundliche Fehlermeldung
                eprintln!("Bitte geben Sie eine gültige positive Zahl ein!");
                continue; // Zurück zum Schleifenanfang, ohne den Versuchszähler zu erhöhen
            }
        };

        // Versuchszähler erhöhen
        versuche += 1;

        // Eingabe mit Geheimzahl vergleichen
        match tipp.cmp(&geheimzahl) {
            Ordering::Less    => println!("Zu niedrig! Versuchen Sie es höher."),
            Ordering::Greater => println!("Zu hoch! Versuchen Sie es niedriger."),
            Ordering::Equal   => {
                println!("🎉 Glückwunsch! Sie haben die Zahl {} erraten!", geheimzahl);
                if versuche == 1 {
                    println!("Das war Ihr erster Versuch – hervorragend!");
                } else {
                    println!("Sie haben {} Versuche benötigt.", versuche);
                }
                break; // Spielschleife beenden
            }
        }

        println!(); // Leerzeile für bessere Lesbarkeit
    }

    println!("Danke für's Spielen! Auf Wiedersehen.");
```

### 6.6 Zeile-für-Zeile-Erklärung

**Import-Anweisungen:**

```rust
use rand::Rng;
```
Bringt den `Rng`-Trait (Random Number Generator) in den Scope. Ohne diesen Import stehen die Methoden des Zufallszahlengenerators nicht zur Verfügung. Ein **Trait** ist in Rust vergleichbar mit einem Interface in anderen Sprachen – er definiert Fähigkeiten, die ein Typ besitzen kann.

```rust
use std::cmp::Ordering;
```
`Ordering` ist ein **Enum** mit drei möglichen Werten: `Less`, `Greater` und `Equal`. Es wird vom `.cmp()`-Methode zurückgegeben, die zwei vergleichbare Werte miteinander vergleicht.

```rust
use std::io;
```
Bringt das `io`-Modul der Standardbibliothek in den Scope. `io` enthält alles, was mit Eingabe und Ausgabe zu tun hat.

**Zufallszahl generieren:**

```rust
let geheimzahl: u32 = rand::thread_rng().gen_range(1..=100);
```

- `rand::thread_rng()`: Erstellt einen Zufallszahlengenerator, der an den aktuellen Thread gebunden ist und kryptographisch sicher geseedet wird
- `.gen_range(1..=100)`: Generiert eine Zufallszahl im Bereich von 1 bis 100 **inklusive** (der `=` macht den Bereich inklusiv)
- `: u32`: Wir speichern die Zahl als vorzeichenlose 32-Bit-Ganzzahl, weil Ratezahlen nie negativ sind

**Die Spielschleife:**

```rust
loop {
```
`loop` erzeugt eine **Endlosschleife**, die nur durch ein explizites `break` oder `return` beendet wird. Das ist die richtige Wahl für unsere Spielschleife, da wir nicht im Voraus wissen, wie viele Versuche der Spieler braucht.

**Eingabepuffer initialisieren:**

```rust
let mut eingabe = String::new();
```
Wichtig: Dieser Code steht **innerhalb** der Schleife. Das bedeutet, bei jedem Schleifendurchlauf wird ein **neuer, leerer** `String` erstellt. Hätte man ihn außerhalb der Schleife, würde die Eingabe des vorherigen Durchlaufs noch im Puffer liegen, da `read_line` den Inhalt **anhängt**, nicht überschreibt.

**Eingabe lesen:**

```rust
io::stdin()
    .read_line(&mut eingabe)
    .expect("Fehler beim Lesen der Eingabe!");
```

- `io::stdin()`: Gibt ein Handle auf die Standard-Eingabe zurück
- `.read_line(&mut eingabe)`: Liest eine Zeile (bis zum Zeilenumbruch) und **hängt** sie an `eingabe` an. Das `&mut` ist eine veränderliche Referenz – `read_line` braucht diese, weil es den String verändert
- `.expect(...)`: Wenn `read_line` einen Fehler zurückgibt (sehr selten, aber möglich), gibt die Panic-Meldung unseren Text aus

**Parsen mit Fehlerbehandlung:**

```rust
let tipp: u32 = match eingabe.trim().parse::<u32>() {
    Ok(zahl) => zahl,
    Err(_) => {
        eprintln!("Bitte geben Sie eine gültige positive Zahl ein!");
        continue;
    }
};
```

Dieser Block enthält mehrere wichtige Konzepte:

- `eingabe.trim()`: Gibt `&str` zurück – den Inhalt von `eingabe`, aber ohne führende/nachfolgende Whitespace-Zeichen (inkl. `\n` und `\r\n`)
- `.parse::<u32>()`: Konvertiert `&str` in `u32`. Der Turbofish-Syntax `::<u32>` gibt explizit den Zieltyp an. Alternativ würde `let tipp: u32 = ...` den Typ inferieren lassen
- `match`: Verarbeitet das `Result<u32, ParseIntError>`
  - `Ok(zahl) => zahl`: Im Erfolgsfall wird `zahl` (die geparste Zahl) zurückgegeben
  - `Err(_) => { ... }`: Im Fehlerfall wird eine Fehlermeldung ausgegeben und die Schleife mit `continue` übersprungen
- `Err(_)`: Das `_` bedeutet: "Ich brauche den Fehler-Wert nicht zu benennen, ich möchte ihn nur ignorieren"
- `eprintln!()`: Gibt die Fehlermeldung auf `stderr` (Standard-Fehlerausgabe) aus statt auf `stdout`. Das ist die professionelle Vorgehensweise für Fehlermeldungen

**Vergleich mit Geheimzahl:**

```rust
match tipp.cmp(&geheimzahl) {
    Ordering::Less    => println!("Zu niedrig! Versuchen Sie es höher."),
    Ordering::Greater => println!("Zu hoch! Versuchen Sie es niedriger."),
    Ordering::Equal   => {
        println!("🎉 Glückwunsch! ...");
        break;
    }
}
```

- `.cmp(&geheimzahl)`: Vergleicht `tipp` mit `geheimzahl` und gibt ein `Ordering` zurück. Das `&` ist notwendig, weil `.cmp()` eine Referenz erwartet
- `Ordering::Less`: `tipp` ist kleiner als `geheimzahl`
- `Ordering::Greater`: `tipp` ist größer als `geheimzahl`
- `Ordering::Equal`: `tipp` ist gleich `geheimzahl` – Gewinn!
- `break`: Beendet die `loop`-Schleife

```rust
use std::io;
```

```rust
    println!("╔════════════════════════════════════════╗");
    println!("║     Willkommen beim Zahlenratespiel!   ║");
    println!("╚════════════════════════════════════════╝");

        print!("Ihr Tipp: ");

        let tipp: u32 = match eingabe.trim().parse::<u32>() {
            Ok(n) if n >= 1 && n <= 100 => n, // Zusätzliche Bereichsprüfung
            Ok(_) => {
                eprintln!("Bitte eine Zahl zwischen 1 und 100 eingeben!");

            Err(_) => {
                eprintln!("Das ist keine gültige Zahl. Bitte erneut versuchen.");
                continue;
            }
        };

        versuche += 1;

        match tipp.cmp(&geheimzahl) {
            Ordering::Less    => println!("↑ Zu niedrig! ({} Versuch{})", 
                versuche, if versuche == 1 { "" } else { "e" }),
            Ordering::Greater => println!("↓ Zu hoch! ({} Versuch{})", 
                versuche, if versuche == 1 { "" } else { "e" }),
            Ordering::Equal   => {
                println!();
                println!("🎉 RICHTIG! Die Zahl war {}!", geheimzahl);
                println!();
                let bewertung = match versuche {
                    1      => "Unglaublich! Erstes Mal richtig!",
                    2..=3  => "Ausgezeichnet! Sehr effizient!",
                    4..=6  => "Gut gemacht!",
                    7..=10 => "Hat etwas gedauert, aber geschafft!",
                    _      => "Durchhalten zahlt sich aus!",
                };
                println!("Bewertung: {} ({} Versuche)", bewertung, versuche);
                break;
            }
        }
    }

    println!();
    println!("Danke für's Spielen!");
}
```

### 8.3 Deep Dive: std::io::stdin und read_line

Die Funktion `read_line` ist komplexer als sie auf den ersten Blick aussieht. Lassen Sie uns ihre Signatur genau betrachten:

```rust
pub fn read_line(&self, buf: &mut String) -> io::Result<usize>
```

- `&self`: `stdin()` nimmt eine Referenz auf sich selbst (das ist ein Methoden-Parameter)
- `buf: &mut String`: Eine **veränderliche Referenz** auf einen `String`. Die Funktion wird in diesen String hineinschreiben
- `io::Result<usize>`: Gibt ein `Result` zurück, das entweder `Ok(n)` (wobei `n` die Anzahl der gelesenen Bytes ist) oder `Err(e)` enthält

**Warum &mut String?**

In Rust kann eine Funktion, die einen Wert verändern möchte, auf zwei Arten damit umgehen:

1. Den Wert **übernehmen** (Ownership) und einen neuen Wert zurückgeben
2. Eine **veränderliche Referenz** nehmen und den Wert direkt modifizieren

`read_line` verwendet Strategie 2. Es nimmt eine `&mut String`, hängt die gelesene Zeile an diesen String an, und gibt die Kontrolle zurück. Der Aufrufer besitzt nach wie vor den `String` und kann ihn weiterverwenden.

**Warum hängt read_line an statt zu überschreiben?**

Diese Designentscheidung ermöglicht es, `read_line` mehrmals aufzurufen und alle gelesenen Zeilen im selben Puffer zu sammeln:

```rust
use std::io::{self, BufRead};

fn main() {
    let stdin = io::stdin();
    let mut gesammelt = String::new();

    // Mehrere Zeilen in denselben Puffer lesen:
    stdin.lock().read_line(&mut gesammelt).unwrap();
    stdin.lock().read_line(&mut gesammelt).unwrap();
    stdin.lock().read_line(&mut gesammelt).unwrap();

    println!("Alle drei Zeilen:\n{}", gesammelt);
}
```

Für unser Zahlenratespiel legen wir deshalb `eingabe` **innerhalb** der Schleife an, damit jede Iteration mit einem frischen, leeren Puffer startet.

### 8.4 Deep Dive: Result<T, E> im Detail

`Result<T, E>` ist Rusts Mechanismus für **explizite Fehlerbehandlung**. Es ist ein Enum mit zwei Varianten:

```rust
enum Result<T, E> {
    Ok(T),   // Erfolg: enthält den Wert vom Typ T
    Err(E),  // Fehler: enthält den Fehler vom Typ E
}
```

Für `parse::<u32>()` ist der konkrete Typ:

```rust
Result<u32, std::num::ParseIntError>
```

Und für `read_line()`:

```rust
Result<usize, std::io::Error>
```

**Die vier Wege, mit Result umzugehen:**

```rust
// Methode 1: unwrap() – Panic bei Fehler
let zahl: u32 = eingabe.trim().parse().unwrap();

// Methode 2: expect() – Panic mit benutzerdefinierter Meldung
let zahl: u32 = eingabe.trim().parse().expect("Konnte Zahl nicht parsen!");

// Methode 3: match – Vollständige Kontrolle
let zahl: u32 = match eingabe.trim().parse::<u32>() {
    Ok(n) => n,
    Err(e) => {
        eprintln!("Fehler: {}", e);
        return;
    }
};

// Methode 4: ? Operator – Fehler nach oben weiterleiten
// (nur in Funktionen, die Result zurückgeben)
fn parse_zahl(eingabe: &str) -> Result<u32, std::num::ParseIntError> {
    let zahl: u32 = eingabe.trim().parse::<u32>()?;
    Ok(zahl)
}
```

| Methode | Verwendung | Verhalten bei Fehler |
|---|---|---|
| `.unwrap()` | Prototyping, wenn Fehler unmöglich | Panic |
| `.expect("msg")` | Wenn Fehler sehr unwahrscheinlich | Panic mit Meldung |
| `match` | Wenn Fehler möglich und behandelbar | Volle Kontrolle |
| `?` | In Funktionen, die `Result` zurückgeben | Fehler weiterleiten |

### 8.5 Deep Dive: Ordering und cmp()

`std::cmp::Ordering` ist ein Enum, das das Ergebnis eines Vergleichs repräsentiert:

```rust
pub enum Ordering {
    Less,    // self < other
    Equal,   // self == other
    Greater, // self > other
}
```

Die Methode `.cmp()` ist Teil des `Ord`-Traits und kann auf allen Typen aufgerufen werden, die eine vollständige Ordnung unterstützen (alle ganzzahligen Typen, `String`, `char` usw.):

```rust
use std::cmp::Ordering;

fn vergleiche(a: i32, b: i32) {
    match a.cmp(&b) {
        Ordering::Less    => println!("{} < {}", a, b),
        Ordering::Equal   => println!("{} == {}", a, b),
        Ordering::Greater => println!("{} > {}", a, b),
    }
}

fn main() {
    vergleiche(3, 5);  // 3 < 5
    vergleiche(7, 7);  // 7 == 7
    vergleiche(9, 2);  // 9 > 2
}
```

### 8.6 Deep Dive: Format-Strings und Platzhalter

Rusts `println!()` Makro unterstützt verschiedene Format-Spezifizierer:

```rust
let name = "Rust";
let zahl = 42;
let pi = 3.14159265;

// {} – Standard-Anzeige (Display-Trait)
println!("{}", name);          // Rust
println!("{}", zahl);          // 42

// {:?} – Debug-Ausgabe (Debug-Trait)
println!("{:?}", name);        // "Rust"
println!("{:?}", zahl);        // 42
println!("{:?}", vec![1,2,3]); // [1, 2, 3]

// {:#?} – Formatierte Debug-Ausgabe (Pretty Print)
println!("{:#?}", vec![1,2,3]);
// [
//     1,
//     2,
//     3,
// ]

// {:5} – Mindestbreite (rechtsbündig)
println!("{:5}", 42);          // "   42"

// {:<5} – Linksbündig
println!("{:<5}", 42);         // "42   "

// {:05} – Mit führenden Nullen
println!("{:05}", 42);         // "00042"

// {:+} – Immer Vorzeichen anzeigen
println!("{:+}", 42);          // "+42"
println!("{:+}", -42);         // "-42"

// {:.2} – Zwei Dezimalstellen
println!("{:.2}", pi);         // "3.14"

// {:8.2} – Breite 8, 2 Dezimalstellen
println!("{:8.2}", pi);        // "    3.14"

// Benannte Argumente:
println!("{name} ist {zahl} Jahre alt", name=name, zahl=zahl);
// Oder in moderner Rust-Syntax:
println!("{name} ist {zahl} Jahre alt");
```

**Der Unterschied zwischen `{}` und `{:?}`:**

- `{}` verwendet den `Display`-Trait: benutzerfreundliche Ausgabe
- `{:?}` verwendet den `Debug`-Trait: Entwickler-freundliche Ausgabe mit Details

Nicht alle Typen implementieren `Display`, aber die meisten implementieren `Debug`. Wenn Sie einen Typ sehen, für den `{}` nicht funktioniert, versuchen Sie `{:?}`.

### 8.7 Deep Dive: stderr vs. stdout

```rust
// stdout – Für normale Ausgaben
println!("Das Ergebnis ist: {}", ergebnis);      // → stdout
print!("Bitte geben Sie etwas ein: ");            // → stdout (ohne Newline)

// stderr – Für Fehlermeldungen
eprintln!("Fehler: Ungültige Eingabe!");          // → stderr
eprint!("Warnung: ");                             // → stderr (ohne Newline)
```

**Warum gibt es stderr?**

Die Trennung von stdout und stderr ermöglicht:

1. **Ausgabe umleiten ohne Fehlermeldungen**:
   ```bash
   ./programm > ausgabe.txt  # Nur stdout in Datei, stderr auf Terminal
   ```

2. **Nur Fehler in Datei speichern**:
   ```bash
   ./programm 2> fehler.log  # Nur stderr in Datei
   ```

3. **Beides in Dateien**:
   ```bash
   ./programm > ausgabe.txt 2> fehler.log
   ```

4. **Beides kombiniert**:
   ```bash
   ./programm > alles.txt 2>&1
   ```

## 4 Alternative: Kommandozeilen-Taschenrechner

Neben dem Zahlenratespiel bietet sich ein einfacher Taschenrechner als alternatives Übungsprojekt an. Er demonstriert dieselben EVA-Prinzipien in einem anderen Kontext.

### 4.1 Anforderungsanalyse

Der Taschenrechner soll:

1. Den Benutzer nach zwei Zahlen fragen
2. Den Benutzer nach dem Operator fragen (`+`, `-`, `*`, `/`)
3. Das Ergebnis berechnen und ausgeben
4. Division durch Null elegant behandeln
5. Ungültige Operatoren mit einer Fehlermeldung ablehnen
6. Mehrere Berechnungen in einer Sitzung ermöglichen

### 4.2 Pseudocode für den Taschenrechner

```
ALGORITHMUS: Taschenrechner

SCHLEIFE (wiederhole bis Benutzer abbricht):
  1. Gib Menü aus
  2. Frage nach erster Zahl
  3. Lese und parse erste Zahl
     WENN ungültig: Fehlermeldung, weiter zu Schritt 2
  4. Frage nach Operator (+, -, *, /, q zum Beenden)
  5. WENN Operator 'q': Programm beenden
  6. Wenn Operator ungültig: Fehlermeldung, weiter zu Schritt 4
  7. Frage nach zweiter Zahl
  8. Lese und parse zweite Zahl
     WENN ungültig: Fehlermeldung, weiter zu Schritt 7
  9. WENN Operator '/' UND zweite Zahl == 0:
       Fehlermeldung "Division durch Null"
       weiter zu Schritt 1
  10. Berechne Ergebnis
  11. Gib Ergebnis aus
ENDE SCHLEIFE
```

### 4.3 Vollständiger lauffähiger Code

```rust
// Datei: src/main.rs
// Kommandozeilen-Taschenrechner – Vollständige Version

use std::io::{self, Write};

fn eingabe_lesen(aufforderung: &str) -> String {
    print!("{}", aufforderung);
    io::stdout().flush().expect("Flush-Fehler!");

    let mut puffer = String::new();
    io::stdin()
        .read_line(&mut puffer)
        .expect("Fehler beim Lesen!");

    puffer.trim().to_string()
}

fn zahl_einlesen(aufforderung: &str) -> f64 {
    loop {
        let text = eingabe_lesen(aufforderung);
        match text.parse::<f64>() {
            Ok(zahl) => return zahl,
            Err(_) => eprintln!("'{}' ist keine gültige Zahl. Bitte erneut versuchen.", text),
        }
    }
}

fn berechne(zahl1: f64, operator: &str, zahl2: f64) -> Result<f64, String> {
    match operator {
        "+" => Ok(zahl1 + zahl2),
        "-" => Ok(zahl1 - zahl2),
        "*" => Ok(zahl1 * zahl2),
        "/" => {
            if zahl2 == 0.0 {
                Err(String::from("Fehler: Division durch Null ist nicht erlaubt!"))
            } else {
                Ok(zahl1 / zahl2)
            }
        }
        "%" => {
            if zahl2 == 0.0 {
                Err(String::from("Fehler: Modulo durch Null ist nicht erlaubt!"))
            } else {
                Ok(zahl1 % zahl2)
            }
        }
        _ => Err(format!("Fehler: '{}' ist kein gültiger Operator!", operator)),
    }
}

fn main() {
    println!("╔══════════════════════════════════════════╗");
    println!("║   Kommandozeilen-Taschenrechner v1.0    ║");
    println!("╚══════════════════════════════════════════╝");
    println!("Operatoren: + - * / %   (q = Beenden)");
    println!();

    loop {
        // Erste Zahl einlesen
        let zahl1 = zahl_einlesen("Erste Zahl: ");

        // Operator einlesen
        let operator: String;
        loop {
            let eingabe = eingabe_lesen("Operator (+, -, *, /, %, q): ");
            if eingabe == "q" || eingabe == "Q" {
                println!("Auf Wiedersehen!");
                return; // Programm beenden
            }
            if ["+", "-", "*", "/", "%"].contains(&eingabe.as_str()) {
                operator = eingabe;
                break;
            }
            eprintln!("Ungültiger Operator '{}'. Bitte +, -, *, / oder % eingeben.", eingabe);
        }

        // Zweite Zahl einlesen
        let zahl2 = zahl_einlesen("Zweite Zahl: ");

        // Berechnung durchführen
        match berechne(zahl1, &operator, zahl2) {
            Ok(ergebnis) => {
                println!("─────────────────────────────────────────");
                println!("  {} {} {} = {}", zahl1, operator, zahl2, ergebnis);

                // Schöne Formatierung für ganze Zahlen
                if ergebnis == ergebnis.floor() && ergebnis.abs() < 1e15_f64 {
                    println!("  (Als ganze Zahl: {})", ergebnis as i64);
                }
                println!("─────────────────────────────────────────");
            }
            Err(fehlermeldung) => {
                eprintln!("{}", fehlermeldung);
            }
        }

        println!();
    }
}
```

### 4.4 Zeile-für-Zeile-Erklärung des Taschenrechners

**Die Hilfsfunktion `eingabe_lesen`:**

```rust
fn eingabe_lesen(aufforderung: &str) -> String {
```
Diese Funktion nimmt einen `&str` (Zeichenketten-Slice) als Aufforderungstext und gibt den eingegebenen Text als `String` zurück. Durch das Auslagern in eine Funktion vermeiden wir Code-Wiederholung (**DRY-Prinzip**: Don't Repeat Yourself).

```rust
    print!("{}", aufforderung);
    io::stdout().flush().expect("Flush-Fehler!");
```
`print!` (ohne `ln`) gibt Text **ohne** Zeilenumbruch aus. Das Problem: Rust puffert Ausgaben, was bedeutet, dass der Text möglicherweise nicht sofort auf dem Bildschirm erscheint. `flush()` erzwingt das sofortige Ausgeben des Pufferinhalts.

**Die Funktion `zahl_einlesen`:**

```rust
fn zahl_einlesen(aufforderung: &str) -> f64 {
    loop {
        let text = eingabe_lesen(aufforderung);
        match text.parse::<f64>() {
            Ok(zahl) => return zahl,
            Err(_) => eprintln!("..."),
        }
    }
}
```
Diese Funktion wiederholt die Eingabeaufforderung so lange, bis eine gültige `f64`-Zahl eingegeben wurde. Das ist eine **Eingabe-Validierungsschleife** – ein wichtiges Muster für robuste Programme.

**Die Funktion `berechne`:**

```rust
fn berechne(zahl1: f64, operator: &str, zahl2: f64) -> Result<f64, String> {
```
Die Funktion gibt `Result<f64, String>` zurück:
- `Ok(f64)`: Das Ergebnis der Berechnung
- `Err(String)`: Eine Fehlermeldung als String

Durch die Rückgabe eines `Result` kann der Aufrufer (unsere `main`-Funktion) entscheiden, wie mit dem Fehler umgegangen wird.

```rust
        "/" => {
            if zahl2 == 0.0 {
                Err(String::from("Fehler: Division durch Null ist nicht erlaubt!"))
            } else {
                Ok(zahl1 / zahl2)
            }
        }
```
Die Division-durch-Null-Behandlung ist explizit implementiert. In Rust würde `1.0_f64 / 0.0_f64` übrigens nicht paniken, sondern `f64::INFINITY` zurückgeben. Für unseren Taschenrechner wollen wir aber eine benutzerfreundliche Fehlermeldung.

### 7.5.1 Der BufRead-Trait

Für komplexere Eingabe-Szenarien bietet Rust den `BufRead`-Trait:

```rust
use std::io::{self, BufRead};

fn main() {
    let stdin = io::stdin();

    println!("Geben Sie mehrere Zeilen ein (Strg+D zum Beenden):");

    for zeile in stdin.lock().lines() {
        match zeile {
            Ok(text) => {

                // text enthält hier KEINE \n am Ende – lines() entfernt das automatisch!
```

| Aspekt | `read_line` | `lines()` Iterator |
|---|---|---|

| Rückgabe | `Result<usize>` | Iterator über `Result<String>` |
| Verwendung | Einzelne Zeile | Mehrere Zeilen |
| Puffer-Management | Manuell | Automatisch |

### 7.5.2 Lesen mehrerer Zeilen

```rust
use std::io::{self, BufRead};

fn lese_zahlen_bis_leer() -> Vec<i32> {
    let stdin = io::stdin();
    let mut zahlen: Vec<i32> = Vec::new();

    println!("Geben Sie Zahlen ein (eine pro Zeile, leere Zeile zum Beenden):");

    for zeile in stdin.lock().lines() {
        let text = zeile.expect("Lesefehler!");

        // Leere Zeile = Ende der Eingabe
        if text.trim().is_empty() {
            break;
        }

        match text.trim().parse::<i32>() {
            Ok(zahl) => {
                zahlen.push(zahl);
                println!("  ✓ {} hinzugefügt (Gesamt: {} Zahlen)", zahl, zahlen.len());
            }
            Err(_) => {
                eprintln!("  ✗ '{}' ist keine gültige Zahl – ignoriert.", text);
            }
        }
    }

    zahlen
}

fn main() {
    let zahlen = lese_zahlen_bis_leer();

    if zahlen.is_empty() {
        println!("Keine Zahlen eingegeben.");
        return;
    }

    let summe: i32 = zahlen.iter().sum();
    let max = zahlen.iter().max().unwrap();
    let min = zahlen.iter().min().unwrap();
    let durchschnitt = summe as f64 / zahlen.len() as f64;

    println!();
    println!("═══════════════════════════");
    println!("Statistik für {} Zahlen:", zahlen.len());
    println!("  Summe:       {}", summe);
    println!("  Maximum:     {}", max);
    println!("  Minimum:     {}", min);
    println!("  Durchschnitt: {:.2}", durchschnitt);
    println!("═══════════════════════════");
}
```

### 7.5.3 Eingabe-Validierungsschleife

Das folgende Muster ist eine der wichtigsten Techniken für robuste Benutzereingaben:

```rust
use std::io;

/// Liest so lange eine Eingabe, bis eine gültige Zahl im gegebenen Bereich eingegeben wird
fn eingabe_mit_bereich(min: i32, max: i32) -> i32 {
    loop {
        let mut puffer = String::new();

        print!("Bitte eine Zahl zwischen {} und {} eingeben: ", min, max);
        use std::io::Write;
        io::stdout().flush().unwrap();

        io::stdin().read_line(&mut puffer).expect("Lesefehler!");

        // Schritt 1: Leerzeichen und Zeilenumbrüche entfernen
        let bereinigt = puffer.trim();

        // Schritt 2: In Zahl konvertieren
        let zahl: i32 = match bereinigt.parse::<i32>() {
            Ok(n) => n,
            Err(_) => {
                eprintln!("'{}' ist keine gültige ganze Zahl!", bereinigt);
                continue; // Schritt 1 wiederholen
            }
        };

        // Schritt 3: Bereich überprüfen
        if zahl < min || zahl > max {
            eprintln!("Die Zahl muss zwischen {} und {} liegen!", min, max);
            continue; // Schritt 1 wiederholen
        }

        // Alle Überprüfungen bestanden – Wert zurückgeben
        return zahl;
    }
}

fn main() {
    println!("Würfelspiel – Setzen Sie auf eine Zahl:");
    let einsatz = eingabe_mit_bereich(1, 6);
    println!("Sie haben auf {} gesetzt.", einsatz);

    // Simulation des Würfelwurfs:
    use std::collections::hash_map::DefaultHasher;
    use std::hash::{Hash, Hasher};
    use std::time::SystemTime;

    let mut hasher = DefaultHasher::new();
    SystemTime::now().hash(&mut hasher);
    let wuerfel = (hasher.finish() % 6 + 1) as i32;

    println!("Der Würfel zeigt: {}", wuerfel);

    if einsatz == wuerfel {
        println!("🎉 Gewonnen!");
    } else {
        println!("Leider verloren. Nächstes Mal vielleicht!");
    }
}
```

> [!NOTE]
> Das Muster `loop { ... continue ... return }` für Eingabe-Validierungsschleifen ist so häufig, dass es sich lohnt, es auswendig zu lernen. Es ist das robusteste Muster für interaktive Benutzereingaben in Rust.

```rust
        }
```

```rust
use std::io::{self, BufRead};

fn mittelwert(zahlen: &[f64]) -> f64 {
    zahlen.iter().sum::<f64>() / zahlen.len() as f64
}

fn median(zahlen: &[f64]) -> f64 {
    let mut sortiert: Vec<f64> = zahlen.to_vec();
    sortiert.sort_by(|a, b| a.partial_cmp(b).unwrap());
    let n = sortiert.len();
    if n % 2 == 0 {
        (sortiert[n / 2 - 1] + sortiert[n / 2]) / 2.0
    } else {
        sortiert[n / 2]
    }
}

fn standardabweichung(zahlen: &[f64]) -> f64 {
    let mw = mittelwert(zahlen);
    let varianz = zahlen.iter()
        .map(|&x| (x - mw).powi(2))
        .sum::<f64>() / zahlen.len() as f64;
    varianz.sqrt()
}

fn histogramm(zahlen: &[f64]) {
    let min = zahlen.iter().cloned().fold(f64::INFINITY, f64::min);
    let max = zahlen.iter().cloned().fold(f64::NEG_INFINITY, f64::max);
    let breite = (max - min) / 5.0;

    println!("Histogramm:");
    for i in 0..5 {
        let von = min + i as f64 * breite;
        let bis = min + (i + 1) as f64 * breite;
        let anzahl = zahlen.iter().filter(|&&x| {
            if i == 4 { x >= von && x <= bis }
            else       { x >= von && x < bis }
        }).count();
        let balken = "█".repeat(anzahl * 3);
        println!("  [{:6.1} – {:6.1}] {} ({})", von, bis, balken, anzahl);
    }
}

fn main() {
    println!("=== Statistik-Rechner ===");
    println!("Geben Sie Zahlen ein (eine pro Zeile, leere Zeile zum Beenden):");

    let stdin = io::stdin();
    let mut zahlen: Vec<f64> = Vec::new();

    for zeile in stdin.lock().lines() {
        let text = zeile.expect("Lesefehler!");
        let bereinigt = text.trim().to_string();

        if bereinigt.is_empty() {
            break;
        }

        match bereinigt.parse::<f64>() {
            Ok(zahl) => {
                zahlen.push(zahl);
                println!("  ✓ {} (n={})", zahl, zahlen.len());
            }
            Err(_) => eprintln!("  ✗ '{}' ignoriert.", bereinigt),
        }
    }

    if zahlen.len() < 2 {
        println!("Zu wenige Zahlen für eine sinnvolle Statistik.");
        return;
    }

    let n = zahlen.len();
    let summe: f64 = zahlen.iter().sum();
    let min = zahlen.iter().cloned().fold(f64::INFINITY, f64::min);
    let max = zahlen.iter().cloned().fold(f64::NEG_INFINITY, f64::max);
    let mw = mittelwert(&zahlen);
    let med = median(&zahlen);
    let std = standardabweichung(&zahlen);

    println!();
    println!("╔════════════════════════════════════╗");
    println!("║           STATISTIK ({} Zahlen)   ║", n);
    println!("╠════════════════════════════════════╣");
    println!("║  Summe:            {:>12.2}     ║", summe);
    println!("║  Minimum:          {:>12.2}     ║", min);
    println!("║  Maximum:          {:>12.2}     ║", max);
    println!("║  Spannweite:       {:>12.2}     ║", max - min);
    println!("║  Arithm. Mittel:   {:>12.2}     ║", mw);
    println!("║  Median:           {:>12.2}     ║", med);
    println!("║  Standardabw.:     {:>12.2}     ║", std);
    println!("╚════════════════════════════════════╝");
    println!();
    histogramm(&zahlen);
}
```

<details>
<summary>Antworten (nur nachschauen, wenn Sie fertig sind!)</summary>

1. `read_line()` gibt `Result<usize>` zurück. Es braucht `&mut String`, weil es den Puffer-String verändert (die gelesene Zeile anhängt) und dafür Schreibzugriff (Mutabilität) benötigt.

2. `read_line()` hängt den Zeilenumbruch (`\n` oder `\r\n`) an den String an. `parse()` würde `"42\n"` nicht als Zahl erkennen.

3. Beide verursachen eine Panic bei `Err`. Der Unterschied: `.expect("Meldung")` gibt eine benutzerdefinierte Fehlermeldung aus; `.unwrap()` gibt eine generische Meldung aus.

4. `Ordering::Less`, `Ordering::Equal`, `Ordering::Greater`

5. Weil `read_line()` den Text an den bestehenden Puffer **anhängt**. Wäre der Puffer außerhalb der Schleife, würden sich die Eingaben aufsammeln.

6. `_` bedeutet "ich ignoriere diesen Wert". `Err(_)` matcht jeden Fehler, ohne ihn zu benennen.

7. `println!` schreibt auf stdout (Standardausgabe). `eprintln!` schreibt auf stderr (Fehlerausgabe). Fehlerausgaben können separat umgeleitet werden.

8. Das `!` markiert Makros in Rust. `println!` ist ein Makro (kein normaler Funktionsaufruf), weil es eine variable Anzahl von Argumenten und Format-Strings unterstützt – etwas, das normale Rust-Funktionen nicht direkt können.

9. `println!("{:.2}", wert)` – der `.2` Teil des Format-Spezifizierers gibt 2 Dezimalstellen an.

10. `[dependencies]` Sektion mit `rand = "0.8"` in `Cargo.toml`.

## 11. Zusammenfassung

In diesem Kapitel haben Sie einen der wichtigsten Meilensteine in Ihrer Rust-Lernreise erreicht: Sie haben das erste vollständige, interaktive Rust-Programm entwickelt – ein Zahlenratespiel – und dabei alle wesentlichen Konzepte der praktischen Programmierung in Rust kennengelernt.

### Was Sie gelernt haben

#### Das EVA-Prinzip in Rust

Das EVA-Prinzip (Eingabe–Verarbeitung–Ausgabe) ist die universelle Struktur jedes Computerprogramms. In Rust bildet sich dieses Prinzip wie folgt ab:

- **Eingabe**: `std::io::stdin().read_line(&mut puffer)` liest eine Zeile Text von der Standardeingabe. Die Methode benötigt eine veränderliche Referenz (`&mut String`), weil sie den Puffer modifiziert.

- **Verarbeitung**: Die Kombination von `.trim()` (Whitespace-Entfernung, inkl. `\n`) und `.parse::<Typ>()` (Typkonvertierung) überführt rohe Texteingaben in nutzbare Datentypen. `Result<T, E>` mit `match` ermöglicht robuste Fehlerbehandlung.

- **Ausgabe**: `println!()` für normale Ausgaben auf stdout, `eprintln!()` für Fehlermeldungen auf stderr.

#### Fehlerbehandlung

Rust's `Result<T, E>` zwingt Sie, mit Fehlern explizit umzugehen. Sie haben vier Strategien kennengelernt:

| Strategie | Verwendung |
|---|---|
| `.unwrap()` | Prototyping; Panic bei Fehler |
| `.expect("msg")` | Wenn Fehler sehr unwahrscheinlich; Panic mit Meldung |
| `match` | Volle Kontrolle; Fehler werden behandelt |
| `?`-Operator | Fehler nach oben weiterleiten (in Result-Funktionen) |

#### Strukturiertes Vorgehen mit Pseudocode

Pseudocode ist kein überflüssiger Schritt – er ist der Unterschied zwischen strukturiertem Programmieren und chaotischem Herumraten. Schreiben Sie zuerst auf Deutsch, was Ihr Programm tun soll, und übersetzen Sie dann Schritt für Schritt in Rust.

#### Wichtige Patterns

```rust
// 1. Sicheres Einlesen mit Validierungsschleife:

    let mut puffer = String::new();                          // INNEN in Schleife
    io::stdin().read_line(&mut puffer).expect("Fehler!");

        Ok(n) => n,
        Err(_) => { eprintln!("Ungültig!"); continue; }

    Ordering::Greater => { /* a > b */ }
```
